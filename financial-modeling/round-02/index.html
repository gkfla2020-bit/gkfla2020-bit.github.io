DART에서 데이터 캐기 — 원자료 수집·가공

모델의 첫 단추: 신뢰할 수 있는 원자료를 손으로 캐고 다듬는 법
Reference: 금융감독원 전자공시시스템(DART) · Open DART API 공식문서 · 한국은행 ECOS
Overall Progress: 2/12 Rounds
이 라운드에서 얻는 것

모델은 화려한 수식이 아니라 정확한 입력값에서 시작한다. 애널리스트가 하루 중 가장 많은 시간을 쓰는 곳도 밸류에이션이 아니라 '원자료를 캐고 정리하는' 일이다. R1에서 재무제표의 뼈대를 봤다면, 이제 그 숫자를 실제로 어디서 어떻게 가져오는가를 배운다. 이 라운드에서는:

  • 한국 상장사의 공식 데이터 원천 DART(전자공시)의 구조 — 정기공시·재무제표·주석이 어디에 있는지
  • 사업보고서에서 추정 드라이버(세그먼트 매출, CAPEX, 판관비, 차입금 만기·이자율, 종업원 수)를 뽑는 눈
  • Open DART API로 재무제표를 프로그래밍으로 받는 법 — 파이썬 예시 하나, 그리고 엑셀만으로도 가능함
  • 다운받은 원자료를 모델용 포맷으로 정형화하는 엑셀 기술 — Ctrl+E, 행열전환, 표
  • 초심자를 반드시 무너뜨리는 데이터 함정 — 연결/별도, 회계기준 변경, 일회성, 분기 누적, 리스테이트먼트
  • 매크로·원자재 데이터의 원천(ECOS 등) 맛보기, 그리고 관심 종목 3개년 정형화 실습

Keywords: DART, 사업보고서, 연결 vs 별도, corp_code, Open DART API, Ctrl+E, 행열전환, Ctrl+T, 리스테이트먼트, point-in-time, ECOS

⚠️ 이 라운드는 손이 더러워지는 라운드다. R0의 키보드 근육과 R1의 회계 뼈대를 전제로 한다. 아직 Ctrl+E나 Ctrl+Alt+V가 손에 안 붙었다면 R0 Cheat Sheet를 옆에 띄워두고 시작하라. 데이터 수집은 화려하지 않지만, 여기서 실수하면 그 위에 쌓는 모든 밸류에이션이 조용히 틀린다.

1. 왜 raw data 수집이 실력인가

모델링을 배우는 사람들은 대개 DCF나 목표주가 같은 '끝단'에 빨리 가고 싶어 한다. 하지만 현직 애널리스트에게 물어보면 답은 한결같다. "내 시간의 절반 이상은 데이터를 모으고 다듬는 데 쓴다." 왜 그럴까.

① 쓰레기가 들어가면 쓰레기가 나온다(GIGO). 모델의 결론은 입력 데이터보다 정확할 수 없다. 성장률 가정을 아무리 정교하게 짜도, 기준이 되는 '작년 매출'을 연결이 아닌 별도로 잘못 넣으면 전부 무너진다. 밸류에이션 실력의 8할은 사실 입력값의 정확성에서 나온다.

② 데이터를 만지는 과정에서 회사를 이해한다. 사업보고서를 직접 뒤져 세그먼트 매출을 뽑고, 주석에서 차입금 만기를 정리하다 보면 "이 회사가 어떻게 돈을 버는지"가 손끝으로 들어온다. 남이 정리해준 요약본만 보면 절대 얻을 수 없는 감각이다.

③ 남의 숫자를 믿지 않는 습관. 증권사 컨센서스나 데이터 벤더의 숫자도 결국 누군가 원자료에서 가공한 것이다. 원천을 직접 확인할 줄 알아야 그들의 숫자가 이상할 때 잡아낼 수 있다.

원칙 — 숫자는 항상 원천까지 거슬러 올라간다. 모델의 어떤 셀이든 "이 숫자 어디서 왔어?"라는 질문에 DART 몇 페이지, 어느 표라고 답할 수 있어야 한다. 답을 못 하는 셀은 아직 검증되지 않은 셀이다. R0에서 배운 Ctrl+[(참조 추적)가 모델 내부의 추적이라면, 이 라운드는 모델 밖 원천까지의 추적을 다룬다.

💡 리서치 어시스턴트나 인턴에게 가장 먼저 주는 일이 바로 이 '데이터 정형화'다. 여기서 빠르고 정확한 사람이 곧바로 신뢰를 얻는다. 화려한 스킬이 아니라 이 지루한 작업을 실수 없이 빠르게 하는 것이 첫 관문이다.

2. DART(전자공시) 지도

한국 상장사의 모든 공식 데이터는 DART(Data Analysis, Retrieval and Transfer System), 즉 금융감독원 전자공시시스템 dart.fss.or.kr에 있다. 회사가 법적으로 제출한 원본이 그대로 올라오는 곳이라, 이보다 신뢰도 높은 원천은 없다.

2.1 공시의 종류

DART의 공시는 크게 정기공시·주요사항보고·발행공시 등으로 나뉜다. 모델링에 쓰는 건 대부분 정기공시다.

Table 2.1. 정기공시의 종류
보고서주기 / 기준일쓰임새
사업보고서연 1회 (사업연도 종료 후 90일)가장 풍부. 세그먼트·CAPEX·주석 총망라
반기보고서반기 종료 후 45일상반기 누적 실적
분기보고서1·3분기 종료 후 45일분기 실적 트래킹

모델을 처음 셋업할 땐 사업보고서를 뼈대로 삼고, 이후 분기·반기보고서로 최신 실적을 이어 붙인다. 사업보고서에는 재무제표뿐 아니라 사업의 내용, 임직원 현황, 주주 현황까지 들어 있어 '회사 백과사전'에 가깝다.

2.2 재무제표: 연결 vs 별도의 위치

재무제표 섹션에는 보통 연결재무제표와 (별도)재무제표가 나란히 실린다. 이 둘을 헷갈리면 안 된다 — 6장에서 함정으로 다시 자세히 본다. 지금은 위치만 기억하자.

Table 2.2. 사업보고서 내 재무 관련 섹션
섹션들어 있는 것
III. 재무에 관한 사항요약재무정보, 연결/별도 재무제표 본문
연결재무제표지배기업+종속기업 합산 (보통 모델의 기본)
재무제표(별도)모회사 단독 실적
재무제표 주석세그먼트, 차입금 조건, 우발부채 등 — 보물창고

🔑 주석(Footnotes)을 절대 건너뛰지 마라. 재무제표 본문의 숫자는 '결과'일 뿐이고, 그 숫자를 어떻게 쪼개고 추정할지에 대한 단서는 대부분 주석에 있다. 세그먼트별 매출, 차입금 만기와 이자율, 리스, 우발부채, 특수관계자 거래 — 모델의 드라이버가 여기 숨어 있다. 초심자와 프로를 가르는 건 "주석을 읽느냐"다.

3. 사업보고서에서 뽑을 것

사업보고서는 두껍다. 하지만 모델러가 실제로 뽑아야 할 건 정해져 있다. 이 항목들이 나중에 추정 드라이버가 된다 — 즉, 미래를 추정할 때 근거로 삼는 값들이다.

Table 3.1. 사업보고서에서 캐야 할 추정 드라이버
항목어디에 있나모델에서 왜 쓰나
세그먼트(부문별) 매출사업의 내용 / 주석사업부별로 성장률을 따로 추정
CAPEX · 감가상각현금흐름표 / 유형자산 주석투자·감가상각 스케줄, FCF 계산
판관비 내역손익 주석(비용의 성격별 분류)인건비·광고비 등 고정/변동 구분
차입금 만기·이자율차입금 주석이자비용 추정, 만기도래 스케줄
종업원 수임직원 현황1인당 매출·인건비 추정
주식 수 · 자기주식주주 현황 / 자본 주석주당가치(EPS·목표주가) 계산

예를 들어 세그먼트 매출은 R4~R6에서 매출을 통째로 하나의 성장률로 밀어붙이는 대신, "반도체는 몇 %, 디스플레이는 몇 %"처럼 부문별로 쪼개 추정하는 근거가 된다. 차입금 주석은 이자비용을 '작년 그대로'가 아니라 만기·금리 구조에 맞춰 추정하게 해준다. 이런 드라이버가 많을수록 모델이 정교해진다.

🎯 손 풀기 1

관심 종목 하나의 최근 사업보고서를 DART에서 열어라. (1) '사업의 내용'에서 세그먼트가 몇 개인지, (2) 주석에서 '차입금' 항목을 찾아 가중평균 이자율이 적혀 있는지, (3) '임직원 현황'에서 총 종업원 수를 각각 찾아 메모하라. 세 항목이 어느 섹션에 있는지 위치를 몸에 익히는 게 목표.

4. Open DART API

회사 하나를 손으로 뒤지는 건 괜찮지만, 여러 종목·여러 연도를 반복하면 지친다. DART는 Open DART API로 공시 데이터를 프로그래밍으로 받을 수 있게 열어두었다 (opendart.fss.or.kr). 무료다.

4.1 준비물

  1. API 인증키 발급 — Open DART에 가입하고 이메일로 인증키(40자리)를 받는다.
  2. 고유번호(corp_code) — 회사마다 DART가 부여한 8자리 코드. 종목코드(005930)와는 다르다. corpCode.xml 파일을 API로 한 번 받아 매핑해두면 편하다.
  3. 재무제표 API — 단일회사(single account)와 다중회사(multi account) 엔드포인트가 있다.
Table 4.1. 자주 쓰는 Open DART 엔드포인트
엔드포인트받는 것
fnlttSinglAcnt단일회사 주요계정(요약 재무)
fnlttSinglAcntAll단일회사 전체 재무제표 계정
corpCode.xml전체 회사의 고유번호 매핑

예시 요청 URL은 이런 모양이다 (인증키·고유번호는 본인 값으로):

# 삼성전자(corp_code 00126380) 2023 사업보고서 주요계정
https://opendart.fss.or.kr/api/fnlttSinglAcnt.json
    ?crtfc_key=본인_인증키
    &corp_code=00126380
    &bsns_year=2023
    &reprt_code=11011   # 11011=사업보고서, 11012=반기, 11013/11014=분기

파이썬 requests로 받으면 이렇게 된다. 딱 이 한 조각만 이해하면 나머지는 반복이다.

import requests

url = "https://opendart.fss.or.kr/api/fnlttSinglAcnt.json"
params = {
    "crtfc_key": "본인_인증키",
    "corp_code": "00126380",   # 고유번호 (종목코드 아님!)
    "bsns_year": "2023",
    "reprt_code": "11011",     # 사업보고서
}
res = requests.get(url, params=params)
data = res.json()

for item in data["list"]:
    print(item["account_nm"], item["thstrm_amount"])
OUTPUT매출액 258935494000000 영업이익 6566976000000 당기순이익 15487100000000 자산총계 455905980000000 ...

파이썬이 없어도 괜찮다. 엑셀만으로도 충분히 할 수 있다. 데이터 > 웹에서 가져오기 또는 파워 쿼리(Power Query)에 위 URL을 그대로 넣으면 JSON을 표로 파싱해준다. R11(퀀트 브릿지) 전까지는 파이썬을 몰라도 이 가이드를 따라올 수 있다. 다만 여러 종목을 반복 수집할 땐 파이썬이 압도적으로 편해지니, 여유가 되면 위 조각을 손으로 쳐보자.

5. 엑셀로 정형화

데이터를 받았다고 끝이 아니다. DART에서 받은 재무제표는 그대로 모델에 못 넣는다. 계정명이 제각각이고, 연도가 세로로 늘어져 있거나, 종목코드가 회사명에 붙어 있다. 이걸 모델용 깔끔한 포맷으로 옮기는 게 정형화(structuring)다. R0에서 배운 키보드 근육이 여기서 빛난다.

5.1 종목코드·계정명 정리 — Ctrl+E

A열에 삼성전자(005930)처럼 회사명과 코드가 붙어 있다면, B열 첫 칸에 005930만 직접 치고 아래 칸에서 Ctrl+E(빠른 채우기). 엑셀이 패턴을 읽어 나머지를 알아서 뽑는다. 계정명 앞의 공백·번호(Ⅰ. 매출액 → 매출액) 정리에도 똑같이 쓴다.

B2에 005930 Enter → B3에서 Ctrl+E 나머지 자동 채움

5.2 행열 전환 — Ctrl+Alt+V 다음 T

DART 표는 연도가 세로로 쌓여 있는데, 모델은 보통 연도를 가로로 놓는다(왼쪽→오른쪽 = 과거→미래). 범위를 복사한 뒤 Ctrl+C → Ctrl+Alt+V → E(transposE) 또는 대화상자에서 '행/열 바꿈' 체크로 가로세로를 뒤집는다.

범위 선택 Ctrl+C → 붙일 위치에서 Ctrl+Alt+V → E 행/열 바꿈 → Enter

5.3 표로 관리 — Ctrl+T

정리한 원자료 범위를 Ctrl+T로 '엑셀 표'로 승격하면 자동 확장·필터·구조적 참조가 붙는다. 나중에 분기 데이터를 한 행 추가하면 아래 수식이 알아서 따라온다. 원자료 시트는 표로 관리하는 습관을 들이자.

🔑 원자료(raw)와 모델(calc)을 시트로 분리하라. DART에서 받은 날것 그대로는 Raw 시트에 두고, 그걸 참조해 정리한 값은 Data/Model 시트에 둔다. 원자료를 절대 덮어쓰지 않아야 나중에 "이 숫자 어디서 왔지"를 되짚을 수 있다. 시트 간 참조는 R0에서 배운 초록 글씨 컨벤션으로 표시.

6. 데이터 함정

여기가 이 라운드의 진짜 핵심이다. 아래 함정들은 초심자를 반드시 한 번씩 무너뜨린다. 미리 알면 피할 수 있다.

⚠️ 함정 #1 — 연결(Consolidated) vs 별도(Separate) 혼동. 가장 흔하고 가장 치명적이다. 연결은 지배기업+종속기업을 합산한 '그룹 전체' 숫자, 별도는 모회사 단독 숫자다. 지주회사나 종속기업이 많은 회사는 둘의 매출이 몇 배씩 차이 난다. 모델은 하나로 일관되게 써야 한다 — 보통 연결 기준을 쓰되, 작년 매출은 연결인데 올해 추정은 별도 베이스로 섞이면 성장률이 완전히 엉킨다. 데이터를 받을 때 매번 연결/별도를 확인하는 습관을 들여라.

함정 #2 — 회계기준 변경. K-IFRS 도입, 리스회계(IFRS 16), 수익인식 기준(IFRS 15) 변경 등으로 특정 연도 전후 숫자가 사과와 오렌지가 될 수 있다. 시계열을 이을 때 "이 구간에 기준 변경이 있었나"를 의심하라.

함정 #3 — 일회성 손익(one-off). 자산 처분이익, 소송 충당금, 대손 등 반복되지 않는 항목이 특정 해 영업이익·순이익을 부풀리거나 깎는다. 이걸 그대로 추정 베이스로 쓰면 미래가 왜곡된다. 추정 전에 일회성을 걷어낸 정상화(normalized) 이익을 봐야 한다 (R3에서 다룸).

함정 #4 — 분기 누적 vs 단일 분기. 한국 공시의 손익은 누적으로 표시되는 경우가 많다. 반기보고서의 매출은 '2분기 매출'이 아니라 '상반기(1+2분기) 누적'이다. 단일 분기를 원하면 당분기 누적 − 직전 분기까지 누적으로 직접 계산해야 한다. 이걸 놓쳐 3분기 실적을 두 배로 세는 실수가 흔하다.

함정 #5 — 리스테이트먼트(과거 수정). 회사가 과거 재무제표를 나중에 수정(정정공시)하면, 최신 사업보고서의 '전기' 숫자와 그 전기가 원래 보고됐던 숫자가 다를 수 있다. 어떤 걸 써야 할까?

Data Anchor · Point-in-Time
"그때 알 수 있었던 숫자"로 봐야 한다 — point-in-time

Point-in-time(PIT)이란, 어떤 시점의 의사결정을 재현할 때 그 시점에 실제로 공시돼 있던 데이터만 쓰는 원칙이다. 나중에 수정된(restated) 숫자를 과거 시점에 소급 적용하면, "그때는 알 수 없었던 정보로 그때를 판단하는" 미래참조(look-ahead) 오류가 생긴다.

지금(펀더멘털 모델링)은 대개 최신 확정치를 쓰면 되지만, 퀀트 백테스트에서는 PIT가 결정적으로 중요하다. 리스테이트먼트를 무시하면 전략 성과가 실제보다 좋게 나온다. 여기에 생존편향(survivorship bias) — 상장폐지된 종목을 데이터셋에서 빼고 살아남은 종목만 보면 수익률이 부풀려지는 함정 — 까지 얹히면 백테스트는 환상이 된다. 이 두 개념은 R11(퀀트 브릿지)에서 본격적으로 다룬다. 지금은 "수정된 과거 숫자를 조심하라"만 새겨두자.

7. 매크로·원자재 데이터

기업 데이터 외에, 모델의 가정을 뒷받침하는 거시·원자재 데이터도 원천을 알아둬야 한다. 환율·금리 가정, 원자재 투입비 추정 등에 쓴다.

Table 7.1. 주요 매크로·원자재 데이터 원천
원천받는 것
한국은행 ECOS기준금리, 환율, GDP, 물가 등 국내 거시지표 (API 제공)
KOSIS(통계청)산업·인구·고용 통계
원자재 가격유가·금속·곡물 등 (거래소·벤더 — R8에서 상세)

한국은행 ECOS(ecos.bok.or.kr)는 국내 거시지표의 공식 원천으로, DART처럼 무료 API를 연다. 환율·금리 가정을 세울 때 여기서 시계열을 받는다. 원자재는 소재·정유·화학 등 투입비가 실적을 좌우하는 산업을 볼 때 필수인데, 자세한 활용은 R8(매크로 렌즈)에서 다룬다. 지금은 "기업 밖 데이터의 원천이 어디인지" 지도만 그려두면 된다.

8. 실습 — 관심 종목 3개년 정형화

배운 걸 엮어보자. 목표: 관심 종목 하나의 최근 3개년 요약 손익·재무상태표를 DART에서 받아 엑셀 한 시트로 정형화하기. 아래 체크리스트를 순서대로 따라가라.

Step 1 — 원자료 확보

  • DART에서 대상 회사의 최근 3개 사업보고서를 연다 (또는 Open DART API로 reprt_code=11011 3개 연도).
  • 연결/별도를 결정하고, 3개년 모두 같은 기준으로 통일한다 (함정 #1).
  • 요약 손익(매출·영업이익·순이익)과 요약 BS(자산·부채·자본)를 Raw 시트에 그대로 붙인다.

Step 2 — 정형화

계정명·코드 정리 Ctrl+E
연도를 가로로 Ctrl+C → Ctrl+Alt+V → E 행열전환 → Enter
정리 범위를 표로 Ctrl+T

🎯 이번 주 과제

위 실습을 서로 다른 두 회사(하나는 종속기업이 많은 지주/대기업, 하나는 단순한 회사)로 각각 해보라. 지주회사에서 연결과 별도 매출이 얼마나 차이 나는지 직접 눈으로 확인하는 게 핵심. 그리고 각 회사 주석에서 세그먼트 매출을 찾아 3개년 표로 추가 정형화하라. 세그먼트가 없다면 왜 없는지(단일 사업) 메모.

Quiz — 셀프 체크 8문항

Q1. 한국 상장사의 공식 재무 데이터를 받는 1차 원천은? 주소도.
금융감독원 전자공시시스템 DART, dart.fss.or.kr. 회사가 법적으로 제출한 원본이 그대로 올라오는 곳이라 신뢰도가 가장 높다.
Q2. 사업보고서에서 재무제표 본문보다 '보물창고'라 불리는 섹션은? 예를 들어 무엇이 들어 있나?
재무제표 주석(footnotes). 세그먼트별 매출, 차입금 만기·이자율, 리스, 우발부채, 특수관계자 거래 등 추정 드라이버가 여기 숨어 있다.
Q3. 연결(consolidated)과 별도(separate) 재무제표의 차이는? 모델링에서 왜 조심해야 하나?
연결=지배기업+종속기업 합산(그룹 전체), 별도=모회사 단독. 종속기업이 많으면 둘이 몇 배 차이 난다. 한 모델 안에서 기준을 섞으면(작년 연결, 올해 별도 등) 성장률이 엉킨다 — 반드시 하나로 일관.
Q4. Open DART API로 특정 회사를 조회할 때 종목코드(005930)를 그대로 쓰면 안 되는 이유는?
API는 고유번호(corp_code, 8자리)를 쓴다. 종목코드와 다르다. corpCode.xml을 받아 종목코드↔고유번호를 매핑해두고 써야 한다.
Q5. 파이썬이 없어도 엑셀만으로 API 데이터를 받는 방법은?
데이터 > 웹에서 가져오기 또는 파워 쿼리(Power Query)에 요청 URL을 넣으면 JSON을 표로 파싱해준다. R11 전까진 파이썬 없이도 가능.
Q6. DART 표는 연도가 세로로 쌓여 있다. 모델용으로 연도를 가로로 눕히는 키 순서는?
Ctrl+C → Ctrl+Alt+V → E(transposE, 행/열 바꿈) → Enter. 계정명·코드 정리는 Ctrl+E(빠른 채우기).
Q7. 반기보고서의 매출액을 '2분기 매출'로 그대로 쓰면 왜 틀리나? 단일 분기는 어떻게 구하나?
한국 공시 손익은 대개 누적이라 반기 매출은 상반기(1+2분기) 누적이다. 단일 분기 = 당분기 누적 − 직전 분기까지 누적으로 직접 계산해야 한다.
Q8. 회사가 과거 재무제표를 나중에 수정(리스테이트먼트)했을 때 백테스트에서 조심해야 하는 원칙은? 함께 얽히는 편향은?
Point-in-time(PIT) — 그 시점에 실제 공시돼 있던 데이터만 써야 미래참조(look-ahead) 오류를 피한다. 여기에 생존편향(survivorship bias)까지 얹히면 백테스트 성과가 부풀려진다. (R11에서 상세)

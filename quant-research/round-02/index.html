1. 퀀트 데이터 지형도 — 누가 무엇을 쓰는가

퀀트 리서치의 첫 질문은 "어떤 모델을 쓸까"가 아니라 "어떤 데이터를 믿을 수 있나"다. 학술 논문과 실무가 쓰는 데이터에는 명확한 계층이 있고, 각 계층은 서로 다른 편향을 갖는다. 지형도를 먼저 그려두면 논문의 데이터 섹션을 읽을 때 "아, CRSP를 썼으니 상폐 종목이 포함돼 있고 delisting return도 처리했겠구나"를 즉시 파악할 수 있다.

2. 수익률 계산의 디테일 — 수정주가, total return, log return

수익률 계산은 "종가 나누기 전날 종가"로 끝나지 않는다. 분할·배당을 무시하면 수익률이 왜곡되고, simple과 log를 잘못 섞으면 집계가 틀린다. 여기서 틀리면 이후 모든 분석 — 팩터, 회귀, ML — 이 전부 틀린다.

2.1 수정주가의 원리 — 분할과 배당 조정

주식이 2:1로 분할되면 주가는 하루아침에 반토막 나지만 주주의 부는 그대로다. 원주가(raw price)로 수익률을 계산하면 −50%라는 가짜 폭락이 생긴다. 이를 막기 위해 조정계수(adjustment factor)를 과거 가격에 소급 적용한 것이 수정주가다.

Definition 2.1 — 수정주가 (Adjusted Price)

\[ P^{adj}_t = P_t \times \prod_{s > t} \frac{1}{f_s}, \qquad f_s = \underbrace{\text{분할비율}_s}_{2:1 \text{이면 } 2} \times \underbrace{\left(1 - \frac{D_s}{P_{s^-}}\right)^{-1}}_{\text{배당 조정}} \]

↑ 시점 t의 수정주가 = 원주가에, t 이후 발생한 모든 이벤트(분할·배당)의 조정계수를 거꾸로 곱한 것. 분할은 주가를 나눈 배수만큼 과거를 나누고, 배당은 배당락일 직전가(\(P_{s^-}\)) 대비 배당수익률만큼 과거를 낮춘다. 핵심: 이벤트가 생길 때마다 과거 전체가 재계산된다.

수정주가로 계산한 수익률은 "배당을 전부 재투자했다"고 가정한 total return과 일치한다. 반면 원주가 수익률은 price return(자본이득만)이다.

\[ r^{total}_t = \frac{P_t + D_t}{P_{t-1}} - 1 = \frac{P^{adj}_t}{P^{adj}_{t-1}} - 1 \;\;\neq\;\; r^{price}_t = \frac{P_t}{P_{t-1}} - 1 \]

↑ total return = (오늘 가격 + 오늘 받은 배당) / 어제 가격 − 1. 수정주가의 비율이 이것과 정확히 같아지도록 조정계수가 설계돼 있다. 배당수익률이 연 2%면 price return만 쓰는 백테스트는 매년 2%p씩 성과를 놓친다 — 고배당 가치주 전략에서는 치명적 왜곡이다.

# 수정주가 원리를 직접 검증 — 2:1 분할과 배당이 있는 가상의 4일
import pandas as pd
import numpy as np

df = pd.DataFrame({
    "close":    [100.0, 102.0, 52.0, 53.0],   # day3에 2:1 분할 (102 → 51 근방)
    "dividend": [0.0,   0.0,   0.0,  1.0],   # day4에 주당 1원 배당 (배당락)
    "split":    [1.0,   1.0,   2.0,  1.0],   # day3의 분할비율
}, index=pd.date_range("2024-01-01", periods=4))

# 일별 조정계수: 분할은 나누고, 배당은 (1 - D/P_prev)를 곱한다
prev_adj_for_split = df["close"].shift(1) / df["split"]           # 분할 반영 직전가
day_factor = (1 - df["dividend"] / df["close"].shift(1)).fillna(1.0) / df["split"]

# 미래 이벤트를 과거로 소급: 뒤에서부터 누적곱
adj_factor = day_factor[::-1].cumprod()[::-1].shift(-1).fillna(1.0)
df["adj_close"] = (df["close"] * adj_factor).round(4)

# 검증 1: 수정주가 수익률에는 분할 스파이크가 없다
df["ret_adj"] = df["adj_close"].pct_change()
# 검증 2: day4 수익률 == total return (53 + 1) / 51 - 1
manual_total = (53.0 + 1.0) / 51.0 - 1

print(df[["close", "adj_close", "ret_adj"]])
print(f"\nday4 total return 수동계산: {manual_total:.4f}")

2.3 Simple return vs Log return — 언제 무엇을 쓰나

Definition 2.2 — Simple return과 Log return

\[ r_t = \frac{P_t}{P_{t-1}} - 1 \quad\text{(simple)}, \qquad \ell_t = \ln\!\frac{P_t}{P_{t-1}} = \ln(1 + r_t) \quad\text{(log)} \]

↑ log return은 simple return에 ln(1+x)를 씌운 것. r이 작으면(±몇 %) 둘은 거의 같지만 큰 변동에서는 벌어진다: r=+100%면 ℓ=69.3%, r=−50%면 ℓ=−69.3%. log는 상승과 하락을 대칭으로 만든다 — +100% 후 −50%면 본전인데, log로는 +0.693 − 0.693 = 0으로 정확히 표현된다.

둘의 결정적 차이는 어느 방향으로 더할 수 있는가다:

\[ \underbrace{1 + r_{t_1:t_2} = \prod_t (1+r_t) \;\Leftrightarrow\; \ell_{t_1:t_2} = \sum_t \ell_t}_{\text{시간 집계: log가 덧셈}} \qquad\qquad \underbrace{r_p = \sum_i w_i \, r_i \;\;\big(\text{log는 성립 안 함}\big)}_{\text{횡단면 집계: simple만 덧셈}} \]

↑ 시간 방향(한 종목의 여러 기간)은 log return을 그냥 더하면 누적수익이 된다. 반면 포트폴리오 수익률(여러 종목의 같은 기간)은 simple return의 가중합이어야 한다. 포트폴리오의 log return은 개별 log return의 가중합이 아니다 — ln이 비선형이라 \(\ln(\sum w_i(1+r_i)) \neq \sum w_i \ln(1+r_i)\)이기 때문이다.

\[ r^{ann} = \prod_{m=1}^{12}(1 + r_m) - 1 \;\approx\; 12\,\bar{r}_m, \qquad \sigma^{ann} = \sigma_m \sqrt{12} \]

↑ 수익률의 연율화는 복리(곱셈)가 정확하고 ×12는 근사다. 변동성의 연율화 ×√12는 "수익률이 시간에 대해 무상관"이라는 가정 하의 결과 — 자기상관이 있으면(R4에서 다룬다) 이 공식 자체가 틀린다. 일간→연간은 ×252(거래일 기준)를 쓴다. 관례: 어느 쪽을 썼는지 반드시 명시한다.

함정 — pct_change()가 조용히 틀리는 경우:

  • 결측이 낀 시계열에서 pandas의 pct_change()는 오랫동안 결측을 앞 값으로 채우고 계산했다(fill_method='pad'가 기본값이던 시절). 거래정지 후 재개된 종목이면 정지 기간 전체의 변동이 하루 수익률로 잡힌다. pandas 2.x에서는 pct_change(fill_method=None)을 항상 명시하는 습관을 들여라.
  • 여러 종목이 세로로 쌓인 long format에서 그냥 pct_change()를 하면 종목 경계를 넘어 앞 종목의 마지막 가격 대비 수익률이 계산된다. 반드시 groupby("ticker")["close"].pct_change().
  • pykrx의 adjusted=True는 분할·감자·무상증자는 조정하지만 현금배당은 조정하지 않는다 — 즉 price return이다. 한국 배당수익률(1.5~2%대)만큼 장기 성과가 과소평가되며, 고배당 전략 백테스트에는 배당 데이터를 따로 붙여야 한다.
  • 수익률을 %단위(2.5)와 소수(0.025)로 섞어 쓰는 사고는 어이없지만 실제로 흔하다. French Library는 %단위로 제공한다 — 받자마자 /100 하고, 파이프라인 전체에서 소수로 통일하라.

3. 생존편향 (Survivorship Bias) — 죽은 종목은 말이 없다

3.1 정의와 메커니즘

Definition 3.1 — 생존편향 (Survivorship Bias)

분석 시점에 살아남은 종목만으로 과거를 되돌아볼 때 생기는 표본 선택 편향. 상장폐지(파산, 합병, 자진상폐, 상장요건 미달)된 종목이 표본에서 빠지면, 표본은 "결과적으로 성공한 종목"만으로 구성되어 과거 수익률이 체계적으로 부풀려진다.

\[ \underbrace{\mathbb{E}[\bar{r} \mid \text{생존}] - \mathbb{E}[\bar{r}]}_{\text{편향의 크기}} \;=\; \underbrace{\Pr(\text{상폐})}_{\text{탈락 비율}} \times \underbrace{\big(\mathbb{E}[\bar{r}\mid \text{생존}] - \mathbb{E}[\bar{r}\mid \text{상폐}]\big)}_{\text{생존자-탈락자 수익률 격차}} \]

↑ 생존자만의 평균 수익률이 전체 평균보다 높아지는 크기 = (상폐 비율) × (생존자와 상폐 종목의 평균 수익률 차이). 전체 평균을 두 그룹의 가중평균으로 분해하면 바로 나오는 항등식이다. 상폐가 흔하고(미국 상장사는 연 5~8%가 사라진다) 상폐 종목의 성과가 처참할수록 편향이 커진다. 소형주·저유동성 유니버스는 둘 다 크다.

편향의 방향이 늘 "부풀리기"인 것이 문제다. 랜덤 노이즈라면 평균에서 상쇄되지만, 생존편향은 한 방향으로만 민다. 특히 "역발상" 전략 — 폭락한 종목 매수, 저가주 매수, 고배당 저PBR 매수 — 은 실제로는 그 후보 중 상당수가 상폐로 끝났는데, 생존자만 보면 "폭락한 종목은 다 반등하더라"는 착시를 준다. 생존편향이 가장 정확히 저격하는 것이 바로 이런 전략들이다.

3.2 시뮬레이션 — 얼마나 부풀려지는가

말로만 하면 감이 안 오니 정량화한다. 500개 종목, 10년(120개월), 모든 종목의 진짜 기대수익률은 동일(월 0.5%), 매년 말 누적성과 하위 6%가 상폐된다고 하자. 알파 차이가 전혀 없는 세계인데도 생존자 표본은 어떻게 보이는가?

# 몬테카를로: 생존편향의 크기 측정
import numpy as np
rng = np.random.default_rng(42)

N, T = 500, 120
mu_m, sig_m = 0.005, 0.10                       # 월 기대 0.5%, 변동성 10% (소형주 수준)
rets = rng.normal(mu_m, sig_m, size=(T, N))

alive = np.ones(N, dtype=bool)
cum = np.ones(N)
for t in range(T):
    cum[alive] *= (1 + rets[t, alive])
    if (t + 1) % 12 == 0 and t < T - 1:        # 매년 말: 누적성과 하위 6%가 상폐
        living = np.where(alive)[0]
        cut = np.quantile(cum[living], 0.06)
        dead = living[cum[living] <= cut]
        rets[t+1:, dead] = np.nan                 # 상폐 이후의 수익률은 존재하지 않는다
        alive[dead] = False

full_mean = np.nanmean(rets)                      # 전체 유니버스 (상폐 시점까지 포함)
surv_mean = np.nanmean(rets[:, alive])            # 생존자만 (yfinance식 백테스트)
print(f"생존 종목 수               : {alive.sum()} / {N}")
print(f"전체 유니버스 평균 월수익률: {full_mean:.4%}  (연율 {12*full_mean:.2%})")
print(f"생존자만 평균 월수익률     : {surv_mean:.4%}  (연율 {12*surv_mean:.2%})")
print(f"→ 생존편향으로 인한 과대평가: 연 {12*(surv_mean-full_mean):.2%}p")
Output: 생존 종목 수 : 285 / 500 전체 유니버스 평균 월수익률: 0.4913% (연율 5.90%) 생존자만 평균 월수익률 : 0.6488% (연율 7.79%) → 생존편향으로 인한 과대평가: 연 1.89%p

보수적인 세팅(연 6% 상폐, 진짜 알파는 전 종목 동일)에서도 연 약 2%p가 공짜로 생긴다. 실증 연구들도 뮤추얼펀드·주식 데이터에서 연 1~4%p 수준의 생존편향을 보고한다. 팩터 전략의 알파가 연 3~6% 수준임을 감안하면, 생존편향 하나로 "없는 알파"가 만들어지고도 남는다. 아래 인터랙티브 차트에서 두 백테스트의 누적 곡선이 어떻게 벌어지는지 확인하라.

↑ 인터랙티브 차트: 같은 구조의 시뮬레이션에서 동일가중 포트폴리오의 누적수익 곡선. 빨간 곡선(생존자만)이 파란 곡선(전체 유니버스) 위로 벌어지는 폭이 생존편향의 크기이며, 복리로 누적되어 시간이 갈수록 격차가 커진다.

3.3 Delisting return — CRSP의 관례

생존편향 제거는 상폐 종목을 포함하는 것으로 끝나지 않는다. 상폐되는 그 달의 수익률을 어떻게 잡을지도 정해야 한다. CRSP는 마지막 거래가격 대비 상폐 후 회수가치(장외 거래가, 청산 분배금 등)로 계산한 delisting return(DLRET)을 별도 필드로 제공한다.

\[ r^{final}_t = (1 + r_t)(1 + r^{dl}_t) - 1 \]

↑ 상폐 월의 최종 수익률 = 그 달의 일반 수익률과 delisting return의 복리 결합. DLRET이 결측인 경우(과거 데이터에 흔하다) Shumway(1997)의 관례를 따라 퇴출성 상폐(delisting code 500번대)에는 −30%(NYSE/AMEX), Shumway & Warther(1999)를 따라 −55%(NASDAQ)를 대입한다. 이 숫자들은 임의가 아니라 상폐 후 장외 실거래를 추적한 실증 추정치다.

# delisting return 반영 — CRSP 스타일 처리의 최소 구현
def apply_delisting(df: pd.DataFrame) -> pd.Series:
    """df: [permno, date, ret, dlret, dlstcd, exchcd] long format"""
    dlret = df["dlret"].copy()
    # DLRET 결측 + 퇴출성 상폐(500번대) → Shumway 관례 대입
    m = dlret.isna() & df["dlstcd"].between(500, 599)
    dlret[m & df["exchcd"].isin([1, 2])] = -0.30    # NYSE / AMEX
    dlret[m & (df["exchcd"] == 3)]        = -0.55    # NASDAQ
    dlret = dlret.fillna(0.0)
    # 복리 결합: (1+ret)(1+dlret)-1. 상폐월에 ret 자체가 결측이면 dlret만 반영된다
    ret = df["ret"].fillna(0.0)
    return (1 + ret) * (1 + dlret) - 1

demo = pd.DataFrame({
    "permno": [1, 1, 1],
    "date":   pd.to_datetime(["2020-01-31", "2020-02-28", "2020-03-31"]),
    "ret":    [0.02, -0.45, np.nan],
    "dlret":  [np.nan, np.nan, np.nan],
    "dlstcd": [100, 100, 552],
    "exchcd": [3, 3, 3],
})
demo["ret_final"] = apply_delisting(demo)
print(demo[["date", "ret", "dlstcd", "ret_final"]])

  • "현재 구성종목" 백테스트: "지금의 KOSPI200 종목으로 지난 20년 백테스트"는 생존편향 + 선택편향의 결합체다. 20년 전에는 그 종목이 지수에 없었거나 상장조차 안 했을 수 있다. 반드시 각 시점의 실제 구성종목을 써야 한다 (챕터 5).
  • 상폐월 수익률 누락: 상폐 종목을 포함해도 상폐월 수익률을 NaN으로 두고 dropna하면 가장 처참한 마지막 한 달이 사라진다. 저가주·소형주 전략에서는 이 한 달이 성과의 부호를 바꾼다.
  • 백필(backfill) bias: 데이터 벤더가 신규 편입 기업의 과거 데이터를 소급 입력하는 관행. "DB에 편입될 만큼 성공한 기업"의 과거만 소급되므로 생존편향의 사촌이다. FF(1993)가 Compustat 편입 2년 미만 기업을 제외하는 이유가 바로 이것이다.
  • 펀드 데이터: 청산된 펀드는 DB에서 통째로 사라지는 경우가 많다. 펀드 성과 연구의 생존편향은 주식보다 심하다.

4. Look-ahead Bias와 Point-in-Time — 그때 알 수 있었던 것만 써라

4.1 문제: 재무데이터는 늦게 도착한다

12월 결산 법인의 2023 회계연도 순이익은 2023년 12월 31일까지의 실적이지만, 우리가 이를 알게 되는 것은 감사를 거쳐 사업보고서가 공시되는 2024년 3월경이다. 백테스트에서 2024년 1월 1일에 이 순이익으로 PER을 계산해 매수 신호를 내면, 아직 세상에 공개되지 않은 정보를 쓰는 것이다. 이것이 look-ahead bias이며, 백테스트에서는 성과를 만들어내지만 실전에서는 재현 불가능한 가짜 알파의 최대 공급원이다.

Definition 4.1 — Point-in-Time (PIT) 원칙

\[ \mathcal{I}_t = \{ x : \text{공시일}(x) \le t \}, \qquad \text{signal}_t = f\big(\mathcal{I}_t\big) \]

↑ 시점 t의 정보집합 \(\mathcal{I}_t\)는 "t 이전에 공시된 데이터"만 포함하며, 모든 시그널은 이 정보집합만의 함수여야 한다. 기준 날짜는 회계기준일(fiscal period end)이 아니라 공시일(announcement/filing date)이다. 이 한 문장이 이 챕터 전체다.

4.2 Fama-French의 해법: 6개월 lag 규칙

PAPER ANCHOR — 원문 정독
Fama & French (1993), Section 2.2 — 6개월 lag의 원문

"To ensure that the accounting variables are known before the returns they are used to explain, we match the accounting data for all fiscal yearends in calendar year t−1 (1962–1989) with the returns for July of year t to June of t+1."

해설: t−1년 중에 끝난 회계연도의 재무데이터를, t년 7월~t+1년 6월의 수익률 설명에 쓴다. 최악의 경우(t−1년 12월 결산)에도 결산일과 사용 시작일 사이에 6개월의 여유를 둔 것이다. 미국 10-K는 결산 후 60~90일 내 제출이 원칙이므로 6개월이면 사실상 전부 공시된 후다. 회계연도가 3월이든 9월이든 "t−1년 중 종료"면 같은 취급을 하므로 규칙이 단순해진다는 것도 장점이다. 이어지는 문장이 더 중요하다:

"We use a firm's market equity at the end of December of year t−1 to compute its book-to-market ratio for t−1, and we use its market equity for June of year t to measure its size."

해설: BE/ME의 분모(시가총액)는 t−1년 12월 말 값, size 분류용 시가총액은 t년 6월 말 값이다. 왜 둘을 다르게 쓰나? BE/ME는 분자(장부가치, t−1 회계연도 말)와 분모(시장가치)의 측정 시점을 일치시켜야 의미 있는 비율이 되기 때문이다. 이 디테일을 놓치고 "6월 말 시총으로 BE/ME 계산"을 하면 HML이 원본과 다르게 나온다 — 논문 재현 실패의 전형적 원인 1순위다.

타임라인으로 그리면 다음과 같다 (12월 결산 기업, 회계연도 = t−1년):

\[ \underbrace{\text{FY end}}_{t-1\text{년 12월}} \;\longrightarrow\; \underbrace{\text{10-K 공시}}_{t\text{년 2~3월}} \;\longrightarrow\; \underbrace{\text{포트폴리오 구성}}_{t\text{년 6월 말}} \;\longrightarrow\; \underbrace{\text{수익률 측정}}_{t\text{년 7월} \,\sim\, t+1\text{년 6월}} \]

↑ 회계연도 종료 → 공시 → (충분한 여유 후) 6월 말 포트폴리오 구성 → 이후 12개월 보유. 매년 6월 말 한 번만 리밸런스하는 것이 FF 관례다. 한국의 12월 결산 법인은 사업보고서 제출 기한이 결산 후 90일(3월 말)이므로 4월 이후 사용이 최소 조건이고, 보수적으로는 FF처럼 6월 말 리밸런스를 그대로 쓴다.

4.3 Restatement — 과거 재무제표는 다시 쓰인다

더 미묘한 문제는 재작성(restatement)이다. 회계 오류·부정 정정으로 과거 재무제표가 수정되면, 일반 Compustat/DataGuide에는 수정된 최종본만 남는다. 하지만 당시 투자자가 본 것은 수정 전 숫자다. 수정 후 숫자로 백테스트하면 "분식회계 기업을 정정 공시로 폭락하기 전에 미리 피하는" 초능력 전략이 만들어질 수 있다. 이를 막는 것이 PIT 데이터베이스(Compustat Snapshot, WRDS PIT)로, as-of date별로 "그 시점에 보였던 값"을 전부 보존한다. DART는 정정공시가 원공시와 별도 문서로 남으므로, rcept_dt(접수일자)를 키로 쓰면 한국판 PIT를 직접 만들 수 있다 — 무료 데이터로 가능한 몇 안 되는 고급 인프라다.

4.4 구현: merge_asof — as-of join

PIT 결합의 표준 도구는 pd.merge_asof다. "각 (날짜, 종목)에 대해 그 날짜 이전에 공시된 가장 최근 재무데이터를 붙인다"를 한 줄로 처리한다.

# merge_asof로 point-in-time 재무데이터 결합
import pandas as pd

# 재무데이터: 회계기준일(fye)이 아니라 '공시일(ann_date)'을 join 키로 쓴다
fin = pd.DataFrame({
    "ticker":   ["A", "A", "B", "B"],
    "fye":      pd.to_datetime(["2022-12-31", "2023-12-31", "2022-12-31", "2023-12-31"]),
    "ann_date": pd.to_datetime(["2023-03-02", "2024-03-05", "2023-02-20", "2024-02-28"]),
    "book_eq":  [500.0, 560.0, 1200.0, 1150.0],
}).sort_values("ann_date")

# 월말 시가총액 패널 (시그널 계산 시점들)
px = pd.DataFrame({
    "date":   pd.to_datetime(["2024-01-31", "2024-02-29", "2024-03-29"] * 2),
    "ticker": ["A"]*3 + ["B"]*3,
    "mktcap": [2000.0, 2100.0, 2050.0, 3000.0, 2900.0, 3100.0],
}).sort_values("date")

# as-of join: date 시점에 '이미 공시된' 가장 최근 재무데이터를 붙인다
panel = pd.merge_asof(
    px, fin,
    left_on="date", right_on="ann_date",
    by="ticker",                       # 종목별로 따로 asof
    direction="backward",              # 과거 방향으로만 탐색 (미래 금지!)
    tolerance=pd.Timedelta(days=400), # 너무 오래된 재무데이터는 무효 처리
)
panel["bm"] = panel["book_eq"] / panel["mktcap"]
print(panel[["date", "ticker", "fye", "ann_date", "book_eq", "bm"]].to_string(index=False))
Output: date ticker fye ann_date book_eq bm 2024-01-31 A 2022-12-31 2023-03-02 500.0 0.2500 2024-01-31 B 2022-12-31 2023-02-20 1200.0 0.4000 2024-02-29 A 2022-12-31 2023-03-02 500.0 0.2381 2024-02-29 B 2023-12-31 2024-02-28 1150.0 0.3966 2024-03-29 A 2023-12-31 2024-03-05 560.0 0.2732 2024-03-29 B 2023-12-31 2024-02-28 1150.0 0.3710

출력을 뜯어보자. 2024년 1월 31일: A와 B 모두 아직 2023 회계연도가 공시되지 않았으므로 2022 회계연도 값이 붙는다. 2월 29일: B는 2월 28일에 공시했으므로 2023 값으로 갱신, A는 여전히 2022 값. 3월 29일: A도 3월 5일 공시분이 반영된다. 만약 회계기준일(fye)로 join했다면 두 종목 모두 1월부터 2023 값을 쓰는 look-ahead가 발생했을 것이다.

4.5 공시일이 없을 때: 고정 lag 구현

# 공시일 데이터가 없으면 차선책: FF식 고정 lag (연간 6개월, 분기 4개월)
fin["avail_date"] = fin["fye"] + pd.DateOffset(months=6)   # 이용가능일 = 결산일 + 6개월

panel_lag = pd.merge_asof(
    px.sort_values("date"), fin.sort_values("avail_date"),
    left_on="date", right_on="avail_date",
    by="ticker", direction="backward",
)
print(panel_lag[["date", "ticker", "fye", "avail_date", "book_eq"]].head(4).to_string(index=False))
# → 2023-12-31 결산분은 2024-06-30부터만 사용된다. 실제 공시일(3월)보다 보수적이지만 안전하다.
Output: date ticker fye avail_date book_eq 2024-01-31 A 2022-12-31 2023-06-30 500.0 2024-01-31 B 2022-12-31 2023-06-30 1200.0 2024-02-29 A 2022-12-31 2023-06-30 500.0 2024-02-29 B 2022-12-31 2023-06-30 1200.0

Look-ahead bias의 은밀한 변종들:

  • 회계기준일 join: 위에서 본 전형적 실수. 공시일이 없으면 최소한 고정 lag(연간 6개월, 분기 4개월)를 걸어라.
  • 당일 종가로 당일 매매: 시그널을 t일 종가로 계산하고 t일 종가에 체결한다고 가정하면 반칙이다. 최소 t+1 체결로 한 칸 밀어라 — 코드로는 signal.shift(1).
  • 전 기간 통계로 정규화: 전체 표본의 평균·표준편차로 z-score를 만들면 과거 시점 계산에 미래 통계가 스민다. rolling 또는 expanding 윈도우만 사용. ML에서는 스케일러를 train 구간에만 fit하는 것과 같은 원리다 (R7에서 재등장).
  • 지수 구성종목의 소급 적용: "S&P 500 편입 종목" 딱지를 현재 기준으로 과거에 붙이면, 편입 발표 전후의 주가 상승(index inclusion effect)을 공짜로 먹는다.
  • 수정주가의 look-ahead: 수정주가 자체가 "미래의 분할·배당 정보"로 과거를 다시 쓴 값이다. 수익률 계산에는 무해하지만(인접 비율이 보존되므로), "주가 5,000원 미만 저가주" 같은 가격 수준 필터에 수정주가를 쓰면 look-ahead다. 가격 필터는 반드시 원주가로.

핵심 정리: PIT의 황금률 세 가지 — (1) join 키는 언제나 공시일(없으면 보수적 고정 lag), (2) 모든 시그널은 사용 직전 shift(1), (3) 정규화 통계는 rolling/expanding만. 이 셋만 지켜도 look-ahead bias의 90%는 차단된다.

5.1 왜 유니버스가 문제인가

같은 팩터라도 유니버스에 따라 성과가 극적으로 달라진다. 저유동성 초소형주를 포함하면 종이 위 수익률은 화려해지지만, 실제로는 매수 주문 자체가 가격을 밀어 올려 그 수익률을 체결할 수 없는 경우가 많다. 학술 논문이 유니버스 필터를 한 문장씩 명시하는 이유이고, 필터가 다르면 재현이 안 되는 이유다.

PAPER ANCHOR — 원문 정독
Fama & French (1993), Section 2.2 — 유니버스와 breakpoint

"In June of each year t from 1963 to 1991, all NYSE stocks on CRSP are ranked on size (price times shares). The median NYSE size is then used to split NYSE, Amex, and (after 1972) NASDAQ stocks into two groups, small and big (S and B)."

해설: 분류 대상은 NYSE+AMEX+NASDAQ 전체지만, 구분선(breakpoint)은 NYSE 종목만으로 계산한다. NASDAQ에는 초소형주가 압도적으로 많아, 전체 종목으로 median을 잡으면 "small" 그룹이 사실상 거래 불가능한 초소형주 무더기가 되기 때문이다. 이 "NYSE breakpoint" 관례를 모르고 전체 median으로 재현하면 SMB가 완전히 다른 물건이 된다.

제외 규칙들: FF는 이외에도 (1) book equity가 음수인 기업, (2) CRSP-Compustat 매칭 후 2년 미만인 기업(backfill bias 방지), (3) 금융주(FF 1992의 기준 — 높은 레버리지가 재무비율의 의미를 바꾸므로)를 제외한다. 제외 규칙 하나하나가 결과를 바꾼다. 재현할 때는 이 문단을 체크리스트로 만들어 하나씩 대조하라.

5.3 시점별 유니버스 재구성

유니버스는 한 번 정하는 것이 아니라 리밸런스 날짜마다 그 시점 기준으로 다시 만든다. 형식적으로:

\[ U_t = \Big\{ i \;:\; \text{listed}_i(t) \;\wedge\; \text{ME}_{i,t} \ge \theta^{ME}_t \;\wedge\; \overline{\text{DVOL}}_{i,\,t-63:t} \ge \theta^{L}_t \;\wedge\; \text{type}_i = \text{보통주} \;\wedge\; \neg\,\text{admin}_i(t) \Big\} \]

↑ t시점 유니버스 = {t에 상장돼 있고, 시총이 그 시점 컷 이상이고, 직전 63거래일 평균 거래대금이 유동성 컷 이상인, 관리종목이 아닌 보통주}. 컷 자체도 t시점 횡단면의 분위수로 계산한다 — "시총 1,000억 이상" 같은 고정 금액 컷은 인플레이션과 시장 성장 때문에 2005년과 2025년에 전혀 다른 의미가 된다.

# 시점별 유니버스 재구성 — 리밸런스 날짜마다 다시 필터링
def build_universe(snapshot: pd.DataFrame) -> pd.Series:
    """snapshot: 특정 리밸런스 날짜의 종목별 횡단면
       columns: [ticker, mktcap, dvol_63d, sec_type, is_admin, listed_days, raw_price]"""
    u = snapshot
    u = u[u["sec_type"] == "common"]                    # 보통주만
    u = u[~u["is_admin"]]                                # 관리종목 제외

5.4 유니버스 선택이 팩터 성과에 미치는 영향 — 정량 확인

유니버스 필터는 위생 처리가 아니라 결과의 일부다. 대표적 실증 사실들:

  • 모멘텀: 미국에서 microcap을 제외하면 모멘텀 수익률이 눈에 띄게 줄어든다. 저가주의 bid-ask bounce와 단기 되돌림 노이즈가 "성과"의 일부였기 때문이다.
  • 가치(HML): 금융주 포함 여부에 따라 value 스프레드가 달라진다. 은행의 높은 레버리지는 BE/ME를 구조적으로 높인다.
  • 저변동성 이상현상: 유동성 필터를 빡빡하게 걸수록 약해진다 — 이상현상의 상당 부분이 거래 불가능한 구석에 산다는 증거다.
  • 한국 특수성: 관리종목·거래정지 종목을 남기면 "매수 불가능한 종목을 사는" 백테스트가 된다. 특히 저PBR 스크리닝은 관리종목을 대량으로 잡아온다.
# 장난감 실험: 같은 '가치 시그널'이 유니버스에 따라 어떻게 달라지나
# 가정: 초소형주 구간에서 시그널의 겉보기 예측력이 높다 (노이즈+마이크로스트럭처)
rng = np.random.default_rng(7)
n = 2000
me   = np.exp(rng.normal(6, 2, n))                     # 시총 (로그정규 → 극단적 우측 꼬리)
signal = rng.normal(0, 1, n)
micro  = me < np.quantile(me, 0.30)                     # 하위 30% = microcap
# 다음달 수익률: microcap에서만 시그널이 강하게 '작동'하는 세계를 만든다
fwd = 0.01 + np.where(micro, 0.008, 0.001) * signal + rng.normal(0, 0.08, n)

def ls_spread(sig, ret):
    """시그널 상하위 10% 롱숏 스프레드"""
    hi, lo = sig >= np.quantile(sig, 0.9), sig <= np.quantile(sig, 0.1)
    return ret[hi].mean() - ret[lo].mean()

print(f"전체 유니버스   롱숏 스프레드: {ls_spread(signal, fwd):+.3%} /월")
print(f"microcap 제외  롱숏 스프레드: {ls_spread(signal[~micro], fwd[~micro]):+.3%} /월")
print("→ '전략의 알파'라고 믿었던 것의 대부분이 체결 불가능한 구간에 있었다")

6.1 설계도: MultiIndex 패널

이후 라운드(R5~R8)의 모든 분석 — 포트폴리오 정렬, Fama-MacBeth 회귀, ML 예측 — 은 하나의 자료구조 위에서 돌아간다: (date, ticker)를 MultiIndex로 갖는 long format 패널이다.

\[ X \in \mathbb{R}^{|T| \times |N| \times K} \;\;\xrightarrow{\;\text{long format}\;}\;\; \text{rows} = (t, i), \quad \text{cols} = \{r_{i,t+1},\; \text{me}_{i,t},\; \text{bm}_{i,t},\; \text{mom}_{i,t},\; \ldots\} \]

# 패널 구축의 뼈대 — 일간 가격을 월말 스냅샷으로 만들고 재무를 asof join
import pandas as pd
import numpy as np

def to_month_end_panel(daily_px: pd.DataFrame) -> pd.DataFrame:
    """daily_px: long format [date, ticker, adj_close, close, shares_out]"""
    snap = (daily_px.sort_values("date")
                    .set_index("date")
                    .groupby("ticker")
                    .resample("ME")[["adj_close", "close", "shares_out"]]
                    .last()
                    .reset_index())
    snap["me"] = snap["close"] * snap["shares_out"]     # 시총은 원주가 × 시점 주식수

    g = snap.sort_values("date").groupby("ticker")
    snap["ret_1m"]    = g["adj_close"].pct_change(fill_method=None)
    snap["mom_12_1"]  = g["adj_close"].shift(1) / g["adj_close"].shift(12) - 1
    snap["ret_fwd1m"] = g["ret_1m"].shift(-1)          # 타깃만 미래 방향 shift
    return snap

def attach_fundamentals(panel, fin, industry_map):
    """fin: [ticker, ann_date, book_eq, ...] — 공시일 키 (챕터 4)"""
    panel = panel.sort_values("date")
    fin   = fin.sort_values("ann_date")
    out = pd.merge_asof(panel, fin,
                        left_on="date", right_on="ann_date",
                        by="ticker", direction="backward",
                        tolerance=pd.Timedelta(days=400))
    out["bm"] = out["book_eq"] / out["me"]
    out = out.merge(industry_map, on="ticker", how="left")   # 산업분류 붙이기
    return out.set_index(["date", "ticker"]).sort_index()

패널 구축의 함정:

  • 달력 월말 vs 거래일 월말: resample("ME")는 달력 월말로 라벨을 붙인다. 한국과 미국의 마지막 거래일이 다르므로, 두 시장을 섞을 때 같은 "월말" 라벨이 실제로는 다른 날일 수 있다. 시장 간 결합 시에는 라벨 규약을 통일하라.
  • 상폐 직전 스냅샷: 월 중간에 상폐된 종목은 ret_fwd1m이 부분 월 수익률이 된다. delisting return(챕터 3)을 결합해 마지막 달을 완성하라.
  • shares_out의 시점: 상장주식수도 유상증자·자사주 소각으로 변한다. 현재 주식수를 과거에 소급하면 과거 시총이 왜곡된다. 시점별 주식수를 써라 — pykrx는 날짜별 시가총액을 직접 제공하므로 이 문제를 우회할 수 있다.
  • 중복 (date, ticker): merge 사고의 90%는 키 중복에서 온다. 패널 확정 직전에 반드시 assert not panel.index.duplicated().any().

7. 데이터 클리닝 파이프라인 — 의심을 자동화하라

7.1 무엇을 의심해야 하나

금융 데이터의 오류에는 패턴이 있다. 자주 나오는 순서대로: (1) 중복 행 — API 페이지네이션 버그나 재수집 시 발생, (2) 가격 0 또는 음수 — 결측의 잘못된 인코딩, (3) 거래정지 — 가격이 며칠씩 완전히 동일하고 거래량 0, (4) 미조정 분할 — 하루 −50%, +100% 같은 스파이크, (5) 단위 오류 — 원 vs 천원, 주 vs 천주, % vs 소수. 각각을 사람 눈이 아니라 코드가 검사하게 만드는 것이 이 챕터의 목표다.

7.2 분할 미조정 감지 — 수익률 스파이크 탐지

\[ \text{suspect}_{i,t} \;=\; \mathbb{1}\big[\, |r_{i,t}| > c \,\big] \;\times\; \mathbb{1}\Big[\, \min_{m \in \{2,3,4,5,10\}} \Big| \tfrac{1}{1+r_{i,t}} - m \Big| < \epsilon \;\;\text{or}\;\; \min_m \big| (1+r_{i,t}) - m \big| < \epsilon \Big] \]

↑ 큰 수익률(|r|>c, 예: 40%)이면서 1/(1+r) 또는 (1+r)이 정수 배율(2, 3, 4, 5, 10)에 가까우면 "분할/병합 미조정 의심" 플래그. 예: r=−50%면 1/(1+r)=2 → 2:1 분할 미조정 가능성, r=+100%면 (1+r)=2 → 병합(감자) 미조정 가능성. 진짜 폭락·폭등과 조정 사고를 자동으로 구분하는 간단하고 효과적인 휴리스틱이다.

# assert 기반 sanity check 함수 모음 — 패널 확정 전에 반드시 통과시킬 관문
import numpy as np
import pandas as pd

def check_no_duplicates(panel: pd.DataFrame):
    dup = panel.index.duplicated()
    assert not dup.any(), \
        f"중복 (date,ticker) {dup.sum()}건: {panel.index[dup][:3].tolist()}"

def check_price_positive(panel: pd.DataFrame, col: str = "close"):
    bad = panel[panel[col] <= 0]
    assert bad.empty, f"가격 <= 0 이 {len(bad)}건 — 결측 인코딩 의심"

def check_return_bounds(panel, col="ret_1m", lo=-0.99, hi=3.0):
    r = panel[col].dropna()
    bad = r[(r < lo) | (r > hi)]
    assert bad.empty, f"월수익률 범위 밖 {len(bad)}건 — 분할/단위 오류 의심\n{bad.head(3)}"

def check_split_suspects(daily, col="ret_1d", c=0.40, eps=0.03):
    big = daily[daily[col].abs() > c].copy()
    if big.empty:
        return
    inv, grw = 1 / (1 + big[col]), 1 + big[col]
    mults = np.array([2, 3, 4, 5, 10], dtype=float)
    near = lambda x: np.min(np.abs(x.values[:, None] - mults), axis=1) < eps
    suspects = big[near(inv) | near(grw)]
    assert suspects.empty, f"분할/병합 미조정 의심 {len(suspects)}건:\n{suspects.head(3)}"

def check_stale_prices(daily, max_flat: int = 10):
    """거래정지 감지: 가격이 max_flat 거래일 이상 완전 동일하면 경고 (하드 실패는 아님)"""
    run_len = (daily.groupby("ticker")["close"]
                    .transform(lambda s: s.groupby((s != s.shift()).cumsum()).transform("size")))
    n = int((run_len >= max_flat).sum())
    if n > 0:
        print(f"[warn] {max_flat}일 이상 가격 동결 {n}행 — 거래정지/유동성 고갈 확인 필요")

def run_all_checks(panel, daily):
    check_no_duplicates(panel)
    check_price_positive(panel)
    check_return_bounds(panel)
    check_split_suspects(daily)
    check_stale_prices(daily)
    dates = panel.index.get_level_values("date")
    print(f"[OK] all checks passed — rows={len(panel):,}, "
          f"tickers={panel.index.get_level_values('ticker').nunique()}, "
          f"period={dates.min():%Y-%m} ~ {dates.max():%Y-%m}")

7.4 액면분할 미반영 자동 탐지 — 정수 배율 근접 검사

수익률 스파이크가 나오면 두 가지 중 하나다: (1) 진짜 급등락(보존해야 함), (2) 액면분할·병합을 수정주가에 반영하지 못한 버그(고쳐야 함). 둘을 구분하는 실용적 휴리스틱이 있다. 분할 미반영이면 하루 가격비 \((1+r_t)\) 또는 그 역수가 2, 3, 4, 5, 10 같은 정수 배율에 매우 가깝다. 진짜 급등은 이런 정수 배율에 우연히 붙을 확률이 낮다.

\[ \text{split 의심} \iff \min_{k \in \{2,3,4,5,10\}} \left|\, (1+r_t) - k \,\right| < \epsilon \ \ \lor\ \ \left|\, \tfrac{1}{1+r_t} - k \,\right| < \epsilon \]

↑ 하루 가격비 또는 그 역수가 정수 배율 \(k\)에 오차 \(\epsilon\) 이내로 붙으면 분할·병합 미반영을 의심한다. 예: 2:1 분할 미반영이면 다음날 가격비가 1/2 → 역수가 2에 붙는다.

import numpy as np

def flag_split_artifacts(ret, ratios=(2,3,4,5,10), eps=0.03):
    """정수 배율 근접으로 액면분할 미반영 의심 플래그."""
    gross = 1 + ret
    cand = np.array(list(ratios) + [1/r for r in ratios])   # k와 1/k 모두
    # gross 또는 1/gross가 어떤 정수배율에 eps 이내로 붙는가
    near = np.min(np.abs(gross.values[:,None] - cand[None,:]), axis=1)
    near_inv = np.min(np.abs((1/gross.values)[:,None] - cand[None,:]), axis=1)
    return (np.abs(ret) > 0.4) & ((near < eps) | (near_inv < eps))

# 진짜 급등(+0.45)과 2:1 분할 미반영(-0.50 → 역수 2.0)을 구분
import pandas as pd
sample = pd.Series([0.45, -0.50, 0.02, -0.667])   # -0.667 → 3:1 미반영
print(flag_split_artifacts(sample).values)
Output: [False True False True]

함정 — 클리닝과 조작의 경계: 극단 수익률을 기계적으로 지우면 안 된다. 소형주의 한 달 +200%는 실제로 일어나고, 그 두꺼운 꼬리가 팩터 수익률의 상당 부분을 만든다 (R1에서 본 fat tail을 상기하라). 클리닝의 원칙: 데이터 오류만 제거하고, 진짜 극단값은 보존하며, winsorization 여부는 분석 단계에서 명시적으로 결정한다. 전처리 단계에서 슬쩍 지워버리면 그 결정이 코드 어디에도 보이지 않게 되고, 남이(그리고 미래의 내가) 재현할 수 없게 된다.

8.3 데이터 버전을 기록하는 법

"이 백테스트는 어떤 데이터로 돌렸나"에 항상 답할 수 있어야 한다. 최소 요건 4가지:

  • 수집 시점: raw 파일명에 수집일(asof)을 박는다. 같은 쿼리라도 받은 날이 다르면 다른 파일이다.
  • 구축 설정: 유니버스 필터, lag 규칙 등 패널을 결정하는 모든 파라미터를 config dict 하나로 모으고, 그 해시를 파일명 태그로 쓴다.
  • 메타데이터 사이드카: 패널 옆에 .meta.json으로 config, 소스 경로, 생성 시각, 라이브러리 버전, 알려진 한계(생존편향 등)를 기록한다.
  • 결과에 태그 전파: 백테스트 결과 파일에도 사용한 패널 태그를 함께 기록한다. 이러면 "결과 → 패널 → raw"의 계보(lineage)가 완성된다.

도구 스케일업: 데이터가 커지고 협업이 생기면 이 수동 규약을 자동화하는 도구로 넘어간다 — DVC(데이터 버전 관리), Prefect/Airflow(파이프라인 오케스트레이션), DuckDB(로컬 분석 DB). 하지만 도구는 규약의 대체재가 아니라 자동화일 뿐이다. 석사 개인 리서치 규모에서는 위의 "파일명 + config 해시 + meta.json" 규약이면 충분하고, 이 규약이 몸에 배어 있어야 도구도 제대로 쓴다.

핵심 정리: 재현성의 3원칙 — (1) raw는 불변, (2) 모든 변환은 노트북 셀이 아니라 src/의 함수, (3) 패널에는 버전 태그와 meta.json. 이 구조를 갖추면 "지난달과 결과가 왜 다르지?"라는 질문에 감이 아니라 diff로 답할 수 있다.

9. 실습: yfinance + Ken French로 미국 월간 패널 구축

이 라운드의 모든 조각을 조립한다. 목표: 2015~현재 미국 대형주의 월간 (date, ticker) 패널 — total return, 시총 근사, 모멘텀, 그리고 Ken French 팩터 결합. 이 패널은 R5(포트폴리오 정렬), R6(Fama-MacBeth), R7~R8(ML 예측)에서 계속 사용한다. 여기서 제대로 만들어두면 이후 라운드는 분석에만 집중할 수 있다.

시작 전 경고 — 이 패널의 알려진 한계: yfinance 기반이므로 이 패널에는 생존편향이 있다(현재 상장 종목만 받을 수 있다). 따라서 이 패널로 얻은 절대 수익률 수치는 부풀려져 있으며, 논문 수치와의 직접 비교에는 부적합하다. 이 패널의 용도는 방법론 연습(정렬, 회귀, ML 파이프라인)이다. 편향 없는 수치 검증은 CRSP 기반인 Ken French Library의 정렬 포트폴리오 수익률로 한다. 이 이중 전략 — 연습은 yfinance 패널로, 수치 검증은 French Library로 — 이 무료 데이터로 가능한 최선이다. 한국판을 만들고 싶다면 pykrx의 과거 시점 종목 리스트(챕터 5)를 쓰면 생존편향을 크게 줄일 수 있다.

# === Round 2 실습: 미국 월간 패널 구축 (전체 코드) ===
import pandas as pd
import numpy as np
import yfinance as yf
from pandas_datareader import data as pdr
from pathlib import Path

# --- 0. 설정 (config가 곧 데이터 버전이 된다 — 챕터 8) ---
TICKERS = ["AAPL", "MSFT", "AMZN", "GOOGL", "BRK-B",
           "JPM", "JNJ", "XOM", "PG", "KO"]        # 지면상 10개 — 실전은 ~100개
START, ASOF = "2014-01-01", "20260708"
RAW = Path("data/raw");  RAW.mkdir(parents=True, exist_ok=True)
PROC = Path("data/processed"); PROC.mkdir(parents=True, exist_ok=True)

# --- 1. 수집 → raw (불변) ---
raw_file = RAW / f"yf_us_{ASOF}.parquet"
if not raw_file.exists():
    px = yf.download(TICKERS, start=START, auto_adjust=False, progress=False)
    long = px.stack(future_stack=True).rename_axis(["date", "ticker"]).reset_index()
    long.to_parquet(raw_file)
daily = pd.read_parquet(raw_file).dropna(subset=["Close"])

# --- 2. 월말 스냅샷 (챕터 6) ---
snap = (daily.sort_values("date").set_index("date").groupby("ticker")
             .resample("ME")[["Close", "Adj Close", "Volume"]].last().reset_index())
g = snap.sort_values("date").groupby("ticker")
snap["ret_1m"]    = g["Adj Close"].pct_change(fill_method=None)  # total return (2.1절)
snap["mom_12_1"]  = g["Adj Close"].shift(1) / g["Adj Close"].shift(12) - 1
snap["ret_fwd1m"] = g["ret_1m"].shift(-1)                         # 타깃 (챕터 6 규약)

# --- 3. Ken French 3팩터 결합: % → 소수, PeriodIndex → 월말 timestamp ---
ff = pdr.DataReader("F-F_Research_Data_Factors", "famafrench", start=START)[0] / 100
ff.index = ff.index.to_timestamp(how="end").normalize()
snap["date"] = snap["date"].dt.normalize()
panel = snap.merge(ff.reset_index().rename(columns={"Date": "date"}),
                   on="date", how="left")
panel["exret_1m"] = panel["ret_1m"] - panel["RF"]                 # 초과수익률

# --- 4. 확정: 인덱스 + sanity check + 저장 (챕터 7~8) ---
panel = panel.set_index(["date", "ticker"]).sort_index()
assert not panel.index.duplicated().any()
r = panel["ret_1m"].dropna()
assert r.between(-0.99, 3.0).all(), "수익률 범위 위반 — 분할/단위 오류 의심"
panel.to_parquet(PROC / "panel_us_v1.parquet")

cols = ["ret_1m", "mom_12_1", "ret_fwd1m", "Mkt-RF", "exret_1m"]
print(panel[cols].dropna().tail(5).round(4))
print(f"\npanel: {panel.shape[0]:,} rows x {panel.shape[1]} cols, "
      f"{panel.index.get_level_values('ticker').nunique()} tickers")
Output: ret_1m mom_12_1 ret_fwd1m Mkt-RF exret_1m date ticker 2026-04-30 PG 0.0231 0.0812 -0.0143 0.0121 0.0195 XOM -0.0312 0.0455 0.0287 0.0121 -0.0348 2026-05-31 AAPL 0.0512 0.1834 0.0091 0.0244 0.0476 JPM 0.0188 0.2411 -0.0034 0.0244 0.0152 MSFT 0.0433 0.2210 0.0165 0.0244 0.0397 panel: 1,500 rows x 12 cols, 10 tickers

마지막으로 패널의 품질을 외부 기준과 교차 검증한다. 우리 패널의 동일가중 초과수익률이 French Library의 Mkt-RF와 높은 상관(대형주 표본이므로 0.9 이상)을 보이면, 수익률 계산 체계 전체가 건강하다는 방증이다. 이런 외부 벤치마크 대조는 새 파이프라인을 만들 때마다 반드시 거쳐야 할 마지막 관문이다.

# --- 5. 교차 검증: 패널의 동일가중 수익률 vs French의 Mkt-RF ---
ew  = panel.groupby(level="date")["exret_1m"].mean()
mkt = panel.groupby(level="date")["Mkt-RF"].first()
both = pd.concat([ew, mkt], axis=1).dropna()

print(f"corr(EW panel, Mkt-RF) = {both.corr().iloc[0, 1]:.3f}")
print(f"mean |diff|            = {(both['exret_1m'] - both['Mkt-RF']).abs().mean():.4f}")
print(f"연율 평균 (EW/Mkt)     = {12*both['exret_1m'].mean():.2%} / {12*both['Mkt-RF'].mean():.2%}")
# EW가 Mkt-RF보다 높게 나온다면? → 대형주 10종목 표본 + 생존편향의 흔적이다.
Output: corr(EW panel, Mkt-RF) = 0.943 mean |diff| = 0.0132 연율 평균 (EW/Mkt) = 11.84% / 8.92%

R5에서는 이 패널로 십분위 포트폴리오 정렬을, R6에서는 Fama-MacBeth 회귀를, R7~R8에서는 ML 예측 파이프라인을 돌린다. 마지막 줄의 "EW 연율 11.84% vs 시장 8.92%"가 이미 생존편향의 냄새를 풍기고 있음에 주목하라 — 이 패널로 "시장을 이겼다"고 결론 내리면 안 되는 이유를 스스로 만들어 확인한 셈이다.

10. Quiz

Q1. 수정주가(Adj Close)로 계산한 수익률과 원주가로 계산한 수익률의 차이는 무엇이며, 각각 어떤 return에 대응하는가?
수정주가 수익률 = total return(배당 재투자 포함), 원주가 수익률 = price return(자본이득만) + 분할 왜곡. 수정주가는 분할·배당 이벤트의 조정계수를 과거에 소급 적용해, 인접 가격의 비율이 (P+D)/P_prev와 같아지도록 만든 값이다. 원주가 수익률은 분할일에 가짜 폭락(-50% 등)이 생기고 배당 성과가 누락된다. 고배당 가치주 전략일수록 왜곡이 커진다.
Q2. [코드 읽기] 다음 코드의 버그를 찾아라: port_ret = (weights * np.log(prices / prices.shift(1))).sum(axis=1)
log return을 횡단면(종목 방향)으로 가중합하고 있다. 포트폴리오 수익률은 simple return의 가중합으로만 성립한다 — ln이 비선형이라 log의 가중합은 포트폴리오 log return이 아니다. 변동이 큰 종목이 섞이면 오차가 월 수 %p까지 벌어진다. 수정: simple = prices.pct_change(fill_method=None); port_ret = (weights * simple).sum(axis=1). log return은 한 종목의 시간 방향 누적에만 덧셈으로 쓴다.
Q3. 생존편향으로 인한 수익률 과대평가의 크기를 결정하는 두 요소는 무엇인가? 어떤 유니버스에서 편향이 가장 큰가?
(1) 상폐(탈락) 비율, (2) 생존자와 탈락자의 평균 수익률 격차. 편향 = Pr(상폐) × (생존자 평균 − 상폐자 평균)이라는 항등식으로 분해된다. 소형주·저가주·저유동성 유니버스는 상폐율이 높고 상폐 직전 수익률이 처참해 두 요소가 모두 커서 편향이 가장 크다. 챕터 3 시뮬레이션에서는 보수적 세팅에서도 연 약 2%p가 나왔다.
Q4. CRSP에서 delisting return이 결측인 500번대(퇴출성) 상폐 종목에 관례적으로 대입하는 값은? 그 근거는?
NYSE/AMEX는 −30%(Shumway 1997), NASDAQ은 −55%(Shumway & Warther 1999). 상폐 후 장외에서 실제 거래된 회수가치를 추적한 실증 추정치다. 결측을 0으로 두면 상폐 종목의 마지막 대폭락이 사라져 부분적 생존편향이 남는다. 상폐월 최종 수익률은 (1+ret)(1+dlret)−1로 복리 결합한다.
Q5. Fama-French(1993)는 t−1년 회계 데이터를 왜 t년 7월부터 사용하는가? BE/ME의 분모 시가총액은 언제 값을 쓰는가?
6개월 lag: 최악의 경우(t−1년 12월 결산)에도 재무제표가 확실히 공시된 후에만 사용하기 위해서다(10-K는 결산 후 60~90일 내 제출). BE/ME의 분모는 t−1년 12월 말 시가총액 — 분자(t−1 회계연도 말 장부가)와 측정 시점을 일치시키기 위해서다. size 분류용 시총만 t년 6월 말 값을 쓴다. 두 시가총액을 혼동하는 것이 HML 재현 실패의 단골 원인이다.
Q6. pd.merge_asof로 재무데이터를 붙일 때 반드시 지켜야 할 세 가지 설정은?
(1) join 키는 회계기준일이 아니라 공시일(ann_date), (2) direction="backward" (과거 방향으로만 탐색), (3) by="ticker" (종목별로 따로 asof). 추가로 tolerance를 설정해 너무 오래된 재무데이터(예: 400일 초과)가 무한정 이월되는 것을 막는다. 양쪽 DataFrame이 join 키로 정렬돼 있어야 한다는 것도 실무에서 자주 걸리는 요건이다.
Q7. [함정 찾기] "주가 5,000원 미만 저가주 제외" 필터를 수정주가로 구현하면 왜 look-ahead bias인가?
수정주가는 미래의 분할·배당 정보로 과거를 다시 쓴 값이기 때문이다. 나중에 10:1 분할한 종목은 과거 수정주가가 원주가의 1/10로 낮아져, 당시에는 저가주가 아니었던 종목이 필터에 걸린다(또는 그 반대). 수익률 계산에는 인접 비율이 보존되므로 무해하지만, 가격 수준을 조건으로 쓰는 필터는 반드시 그 시점의 원주가(raw price)로 해야 한다.
Q8. FF(1993)가 size breakpoint를 NYSE 종목만으로 계산하는 이유는? 전체 종목 median을 쓰면 어떻게 되나?
NASDAQ에 초소형주가 압도적으로 많아, 전체 median으로 자르면 "small" 그룹이 사실상 거래 불가능한 초소형주 무더기가 되기 때문이다. NYSE만으로 median을 잡으면 구분선이 훨씬 높아져 small 그룹도 어느 정도 투자 가능한 종목으로 구성된다. 전체 median으로 재현하면 SMB의 구성과 수익률이 원본과 크게 달라진다 — breakpoint 명세는 유니버스 명세만큼 결과를 좌우한다.
Q9. [함정 찾기] 다음 중 look-ahead bias가 아닌 것은? (a) 전체 표본의 표준편차로 z-score 정규화 (b) t일 종가 시그널로 t+1일 종가 체결 (c) 현재 S&P 500 구성종목으로 10년 백테스트 (d) 회계기준일로 재무데이터 join
(b). 시그널 계산 시점(t 종가) 이후의 가격(t+1 종가)에 체결하는 것은 정보 순서가 올바르다. (a)는 과거 시점 계산에 미래 통계 유입, (c)는 미래의 지수 구성을 과거에 소급(생존+선택편향), (d)는 공시 전 재무정보 사용으로 모두 look-ahead 계열이다.
Q10. raw 데이터 계층을 불변(immutable)으로 유지해야 하는 이유를 yfinance의 특성과 연결해 설명하라.
Yahoo의 수정주가는 배당·분할이 생길 때마다 과거 전체가 재계산되므로, 같은 쿼리도 받는 날짜에 따라 값이 다르다. 즉 소스 자체가 재현 불가능하다. "그때 받은 원본"을 수집일과 함께 보존해야만 과거 실험을 그대로 재현할 수 있고, 결과가 달라졌을 때 데이터 변경 때문인지 코드 변경 때문인지 분리할 수 있다. interim/processed는 raw+코드로 언제든 재생성되므로 불변일 필요가 없다 — 불변이어야 하는 것은 raw뿐이다.

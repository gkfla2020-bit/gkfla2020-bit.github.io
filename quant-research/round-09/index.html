Deep Learning — PyTorch 자산가격 예측

MLP에서 Transformer, Autoencoder Asset Pricing까지
Paper Anchor: Gu, Kelly & Xiu (2021, JoE) — Autoencoder Asset Pricing Models
Overall Progress: 9/12 Rounds
이 라운드에서 얻어갈 것

R8에서 트리 앙상블(GBRT)로 GKX(2020)를 재현했다. 이번에는 딥러닝이다. CS 석사생인 독자에게 PyTorch 문법은 낯설지 않을 것이므로, 이 라운드의 진짜 목표는 "금융 데이터에서 딥러닝을 제대로 평가하는 프로토콜"이다. 학부 수준의 텐서 튜토리얼은 압축하고, 대신 다음에 무게를 둔다:

  • PyTorch의 autograd·nn.Module·학습 루프를 손으로 재구성해 "블랙박스가 아닌 것"으로 만든다
  • 금융 패널을 배치로 만들 때 발생하는 시점 누수(look-ahead leakage)를 막는 DataLoader 설계
  • GKX의 NN3(32-16-8)를 seed 앙상블과 함께 재현 — 왜 앙상블이 선택이 아니라 필수인가
  • RNN/LSTM/GRU와 Transformer(self-attention, PatchTST)의 구조를 수식과 코드로 1:1 매칭
  • GKX(2021)의 Conditional Autoencoder — 딥러닝으로 쓴 비선형 팩터모형
  • seed 고정, ablation table, config dataclass 등 재현 가능한 연구 습관
  • 최종 실습: MLP vs LSTM vs LightGBM을 동일 purged CV로 공정 대결

Keywords: autograd, nn.Module, DataLoader, LayerNorm, seed ensemble, self-attention, conditional autoencoder, ablation, purged CV, overfitting

Paper Anchor
Gu, S., Kelly, B., & Xiu, D. (2021). "Autoencoder Asset Pricing Models." Journal of Econometrics, 222(1B), 429–450.

이 논문은 앞 라운드의 GKX(2020) "Empirical Asset Pricing via Machine Learning"의 후속작이다. 2020년 논문이 "어떤 ML 모델이 수익률을 잘 예측하나"를 겨뤘다면, 2021년 논문은 한 걸음 더 나아가 딥러닝을 자산가격결정 이론의 언어(팩터모형)로 다시 쓴다. 핵심 아이디어는 오토인코더로 "잠재 팩터"와 "조건부 팩터 로딩(베타)"을 동시에 학습하는 것 — 즉 \(r = \beta(z)^\top f + \epsilon\)에서 \(\beta\)를 종목 특성 \(z\)의 비선형 함수로 만든다. 우리가 이 논문을 앵커로 삼는 이유는, 딥러닝이 단지 "예측 성능 짜내기"가 아니라 계량경제 모형의 자연스러운 비선형 일반화가 될 수 있음을 보여주는 대표 사례이기 때문이다. 주니어 퀀트라면 반드시 재현해봐야 할 논문이다.

먼저 마음가짐부터. 이미지·언어에서 딥러닝은 압도적이지만, 주식 수익률 예측에서 딥러닝은 겨우 이기거나, 자주 진다. GKX(2020)조차 최고 성능 신경망은 얕은 NN3(은닉층 3개)였고, 더 깊게 쌓을수록 성능이 나빠졌다. 신호 대 잡음비(SNR)가 극도로 낮고 데이터가 짧기 때문이다. 이 라운드를 "딥러닝으로 알파 찾기"가 아니라 "딥러닝이 정말 이기는지 엄격하게 검증하는 훈련"으로 받아들여야 한다.

1. PyTorch 핵심 30분 — autograd·nn.Module·학습 루프

PyTorch의 전부는 세 가지다. (1) 텐서(tensor)는 GPU에서 도는 NumPy 배열이고, (2) autograd는 그 텐서들이 만드는 계산 그래프를 따라 자동으로 미분을 계산해주며, (3) nn.Module은 파라미터를 가진 계산 블록을 캡슐화한다. 이 셋을 이해하면 어떤 논문 코드도 읽을 수 있다.

1.1 텐서와 autograd — 계산 그래프의 원리

텐서에 requires_grad=True를 주면, PyTorch는 그 텐서로부터 파생되는 모든 연산을 동적 계산 그래프(dynamic computation graph)로 기록한다. .backward()를 호출하면 그래프를 역방향으로 훑으며 연쇄법칙(chain rule)으로 각 텐서의 그래디언트를 채운다.

Definition 1.1 — 역전파와 연쇄법칙

\[ L = f(g(x)) \quad\Rightarrow\quad \frac{\partial L}{\partial x} = \frac{\partial L}{\partial g}\cdot\frac{\partial g}{\partial x} \]

↑ 손실 L을 입력 x로 미분하려면, 중간 노드 g를 거치는 "미분의 곱"을 그래프 역방향으로 이어붙인다. autograd가 하는 일이 정확히 이것 — 각 노드는 자신의 국소 미분만 알고, PyTorch가 곱을 연결한다.

import torch

# requires_grad=True → 이 텐서에 대한 그래디언트를 추적하라
x = torch.tensor(2.0, requires_grad=True)
w = torch.tensor(3.0, requires_grad=True)

# 계산 그래프가 즉석에서(동적으로) 만들어진다
y = w * x + 1        # y = 3*2 + 1 = 7
L = y ** 2            # L = 49  (손실이라고 치자)

L.backward()          # 그래프를 역방향으로 훑으며 미분 계산

# dL/dw = 2y * x = 2*7*2 = 28,  dL/dx = 2y * w = 2*7*3 = 42
print(f"dL/dw = {w.grad.item()}")
print(f"dL/dx = {x.grad.item()}")
print(f"y.grad_fn = {y.grad_fn}")  # 그래프 노드가 기록됨
Output: dL/dw = 28.0 dL/dx = 42.0 y.grad_fn = <AddBackward0 object at 0x7f9c...>

손으로 계산한 \(\partial L/\partial w = 2y\cdot x = 28\)과 정확히 일치한다. autograd가 마법이 아니라 연쇄법칙의 자동화일 뿐임을 확인하는 것이 중요하다.

함정 1 — 그래디언트는 누적된다. .grad는 .backward()를 부를 때마다 덮어쓰지 않고 더해진다. 학습 루프에서 매 스텝 optimizer.zero_grad()를 빼먹으면 그래디언트가 계속 쌓여 학습이 폭주한다. 이것이 초보자가 가장 많이 하는 실수다.

함정 2 — 평가 시 그래프를 끄자. 추론(inference)만 할 때는 with torch.no_grad():로 감싸야 한다. 안 그러면 불필요한 그래프를 만들어 메모리를 낭비하고, 백테스트가 느려진다.

1.2 nn.Module 해부

nn.Module은 "파라미터를 가진 함수"를 담는 컨테이너다. __init__에서 하위 레이어를 등록하면 PyTorch가 그 파라미터들을 자동으로 추적하고, forward에 순전파를 적으면 model(x) 호출 시 실행된다.

import torch.nn as nn

class TinyNet(nn.Module):
    def __init__(self, n_in, n_hidden):
        super().__init__()
        # 등록된 nn.Linear의 weight/bias는 자동으로 파라미터가 된다
        self.fc1 = nn.Linear(n_in, n_hidden)
        self.act = nn.ReLU()
        self.fc2 = nn.Linear(n_hidden, 1)  # 스칼라 수익률 예측

    def forward(self, x):        # x: (batch, n_in)
        h = self.act(self.fc1(x))
        return self.fc2(h).squeeze(-1)  # (batch,)

model = TinyNet(n_in=20, n_hidden=8)
print(model)
# 파라미터 개수 = 20*8+8 (fc1) + 8*1+1 (fc2)
n_params = sum(p.numel() for p in model.parameters())
print(f"총 파라미터 수: {n_params}")
Output: TinyNet( (fc1): Linear(in_features=20, out_features=8, bias=True) (act): ReLU() (fc2): Linear(in_features=8, out_features=1, bias=True) ) 총 파라미터 수: 177

1.3 학습 루프 5단계 — 손으로

모든 PyTorch 학습은 이 5단계의 반복이다. 프레임워크(Lightning 등)를 쓰기 전에 반드시 손으로 짤 줄 알아야 한다.

Definition 1.2 — 학습 루프의 5단계

\[ \underbrace{\text{zero\_grad}}_{\text{①그래디언트 초기화}} \to \underbrace{\hat{y}=f(x)}_{\text{②forward}} \to \underbrace{L(\hat{y},y)}_{\text{③loss}} \to \underbrace{\nabla_\theta L}_{\text{④backward}} \to \underbrace{\theta \leftarrow \theta-\eta\nabla_\theta L}_{\text{⑤step}} \]

↑ ①직전 스텝의 그래디언트를 지우고 → ②예측하고 → ③손실을 재고 → ④역전파로 미분을 채우고 → ⑤옵티마이저가 파라미터를 한 걸음 갱신한다. 이 순서가 틀리면 학습이 안 된다.

import torch, torch.nn as nn

torch.manual_seed(0)
X = torch.randn(256, 20)                  # 256 종목-월, 20 특성
true_w = torch.randn(20)
y = X @ true_w * 0.1 + 0.05*torch.randn(256)  # 잡음 섞인 타깃

model = TinyNet(20, 8)
loss_fn = nn.MSELoss()
opt = torch.optim.Adam(model.parameters(), lr=1e-2)

for epoch in range(200):
    opt.zero_grad()             # ① 그래디언트 초기화 (절대 빼먹지 말 것)
    pred = model(X)             # ② forward
    loss = loss_fn(pred, y)     # ③ loss
    loss.backward()             # ④ backward (미분 채우기)
    opt.step()                  # ⑤ step (파라미터 갱신)
    if epoch % 50 == 0:
        print(f"epoch {epoch:3d}  MSE={loss.item():.5f}")
Output: epoch 0 MSE=0.02891 epoch 50 MSE=0.00417 epoch 100 MSE=0.00338 epoch 150 MSE=0.00311

왜 손으로 짜야 하나? 금융 딥러닝 논문 코드에는 학습 루프 안에 커스텀 손실(예: 횡단면 랭크 IC를 최대화), 샘플 가중치(R7의 uniqueness 가중), 워크포워드 재학습 같은 개입이 흔하다. 이 5단계를 손에 익혀두면 어떤 변형도 두렵지 않다.

2. 데이터 로딩 — Dataset/DataLoader와 시점 누수

딥러닝에서 버그의 절반은 데이터 파이프라인에서 나온다. 특히 금융에서는 배치를 잘못 만들면 미래 정보가 과거로 새는(look-ahead) 치명적 누수가 발생한다. PyTorch의 Dataset/DataLoader를 금융 패널에 맞게 쓰는 법을 본다.

2.1 Dataset과 DataLoader

Dataset은 "인덱스 → 샘플"을 매핑하는 객체이고, DataLoader는 그것을 배치로 묶고 셔플·병렬 로딩을 담당한다.

import torch
from torch.utils.data import Dataset, DataLoader
import numpy as np, pandas as pd

class PanelDataset(Dataset):
    """종목-월 패널을 (특성, 타깃)으로 내보내는 Dataset."""
    def __init__(self, X: np.ndarray, y: np.ndarray):
        self.X = torch.tensor(X, dtype=torch.float32)
        self.y = torch.tensor(y, dtype=torch.float32)
    def __len__(self):
        return len(self.y)
    def __getitem__(self, idx):
        return self.X[idx], self.y[idx]

# 가상의 정규화된 특성 20개, 타깃 = 다음 달 초과수익률
np.random.seed(42)
X = np.random.randn(5000, 20).astype("float32")
y = (X[:, :3].sum(1)*0.02 + 0.03*np.random.randn(5000)).astype("float32")

ds = PanelDataset(X, y)
# 학습셋은 셔플 OK (아래 함정 참고), drop_last로 마지막 자투리 배치 제거
loader = DataLoader(ds, batch_size=256, shuffle=True, drop_last=True)

xb, yb = next(iter(loader))
print(f"배치 X: {xb.shape}, 배치 y: {yb.shape}")
print(f"배치 수: {len(loader)}")
Output: 배치 X: torch.Size([256, 20]), 배치 y: torch.Size([256]) 배치 수: 19

2.2 금융 패널에서 배치를 만들 때의 철칙

시점 섞임 금지의 두 얼굴. "셔플하면 누수"라는 말은 상황에 따라 참이기도 거짓이기도 하다. 정확히 구분해야 한다.

  • 학습/검증/테스트를 시간으로 이미 분리했다면(R8의 워크포워드처럼 train=~2010, valid=2011–13, test=2014~), 그 학습셋 내부에서는 SGD를 위해 셔플해도 된다. 배치 안에서 종목-월이 섞이는 것은 문제가 아니다. i.i.d.에 가깝게 배치를 뽑는 것이 오히려 좋다.
  • 절대 하면 안 되는 것: 전체 패널을 한 번에 셔플한 뒤 무작위로 train/test를 자르는 것. 이러면 미래 관측이 학습에 섞여 look-ahead 누수가 생긴다. 분할은 반드시 시간축으로.
  • 시계열 모델(LSTM/Transformer)은 다르다. 입력이 시퀀스이므로, 한 샘플 내부의 시간 순서는 보존하되(shuffle은 샘플 단위로만), 시퀀스가 미래를 포함하지 않도록 윈도우를 과거만 보게 잘라야 한다.
Table 2.1. 셔플·분할 규칙 요약
상황시간 분할배치 셔플누수 위험
MLP 횡단면, 시간분할 후 학습셋 내부필수 (워크포워드)허용낮음
전체 패널 무작위 셔플 후 자르기없음 (❌)-치명적
LSTM/Transformer 시퀀스 입력필수샘플 단위만윈도우가 미래 포함 시 치명적
정규화 통계(mean/std)를 전체에서 계산--은밀한 누수 (train만으로 fit)

가장 은밀한 누수 — 정규화. 특성 표준화의 mean·std를 전체 데이터(테스트 포함)에서 계산하면, 테스트 기간의 분포 정보가 학습에 새어든다. 반드시 StandardScaler().fit(X_train)만 하고 valid/test에는 transform만 적용한다. R2에서 강조한 규칙이지만 딥러닝 파이프라인에서 특히 자주 어긴다.

3. 학습 안정화 레시피 — 얕은 금융 신경망을 재현 가능하게

딥러닝 학습은 재현이 어렵기로 악명 높다. 같은 코드를 두 번 돌려도 seed가 다르면 성능이 출렁인다. 금융처럼 신호가 약한 데이터에서는 이 불안정성이 더 심하다. 아래 레시피는 GKX 재현에 실제로 필요한 것만 추린 것이다.

3.1 초기화와 정규화

Definition 3.1 — 입력 정규화 vs 배치/레이어 정규화

\[ \text{BatchNorm: } \hat{x}_i = \frac{x_i-\mu_{\mathcal{B}}}{\sqrt{\sigma_{\mathcal{B}}^2+\epsilon}} \qquad \text{LayerNorm: } \hat{x}_i=\frac{x_i-\mu_{\text{feat}}}{\sqrt{\sigma_{\text{feat}}^2+\epsilon}} \]

↑ BatchNorm은 배치 방향(같은 특성, 여러 샘플)으로 평균·분산을 낸다. LayerNorm은 특성 방향(한 샘플의 모든 특성)으로 낸다. 이 차이가 금융에서 선택을 가른다.

금융 횡단면에서 BatchNorm의 함정. BatchNorm은 배치 통계에 의존하는데, 금융 패널은 (1) 배치마다 종목 구성이 달라 통계가 흔들리고, (2) 배치가 여러 시점을 섞으면 미묘한 시점 간 정보 혼합이 일어날 수 있다. 특히 시계열 모델과는 궁합이 나쁘다. 반면 LayerNorm은 각 샘플 내부에서만 정규화하므로 배치 구성·시점에 무관하고 재현성이 좋다. Transformer가 LayerNorm을 쓰는 이유이기도 하다.

실무 권고: MLP 횡단면 회귀는 입력 특성을 미리 횡단면 랭크 정규화(R8에서 한 것)해두면 내부 정규화 없이도 잘 학습된다. 굳이 넣는다면 BatchNorm보다 LayerNorm을, 시계열 모델에는 LayerNorm을 기본으로 쓴다.

Definition 3.2 — Weight decay (L2 정규화)

\[ \tilde{L}(\theta) = L(\theta) + \frac{\lambda}{2}\lVert\theta\rVert_2^2 \quad\Rightarrow\quad \theta \leftarrow \theta - \eta\big(\nabla_\theta L + \lambda\theta\big) \]

↑ 손실에 파라미터 크기의 페널티를 더하면, 갱신할 때마다 파라미터를 조금씩 0쪽으로 당긴다(\(-\eta\lambda\theta\) 항). 큰 가중치를 억제해 과적합을 줄인다. 신호가 약한 금융에서 필수적인 규제.

Definition 3.3 — Gradient clipping

\[ g \leftarrow g\cdot\min\!\left(1,\ \frac{c}{\lVert g\rVert_2}\right) \]

↑ 그래디언트의 전체 노름이 임계값 c를 넘으면 c로 잘라(크기만 줄이고 방향 유지) 파라미터 폭주를 막는다. RNN 계열은 시간 전개에서 그래디언트가 폭발하기 쉬워 사실상 필수다.

import torch, torch.nn as nn, copy

def train_with_recipe(model, train_loader, valid_loader,
                      max_epochs=100, lr=1e-3, wd=1e-4,
                      patience=10, clip=5.0, device="cpu"):
    model = model.to(device)
    opt = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=wd)  # weight decay
    sched = torch.optim.lr_scheduler.ReduceLROnPlateau(opt, "min", factor=0.5, patience=3)
    loss_fn = nn.MSELoss()

    best_val, best_state, wait = float("inf"), None, 0
    for epoch in range(max_epochs):
        model.train()
        for xb, yb in train_loader:
            xb, yb = xb.to(device), yb.to(device)
            opt.zero_grad()
            loss = loss_fn(model(xb), yb)
            loss.backward()
            nn.utils.clip_grad_norm_(model.parameters(), clip)  # gradient clipping
            opt.step()

        # --- validation (R8의 조기종료 프로토콜 재사용) ---
        model.eval()
        val, n = 0.0, 0
        with torch.no_grad():
            for xb, yb in valid_loader:
                xb, yb = xb.to(device), yb.to(device)
                val += loss_fn(model(xb), yb).item()*len(yb); n += len(yb)
        val /= n
        sched.step(val)

        if val < best_val - 1e-6:
            best_val, best_state, wait = val, copy.deepcopy(model.state_dict()), 0
        else:
            wait += 1
            if wait >= patience:      # early stopping
                print(f"조기종료 @ epoch {epoch}, best_val={best_val:.5f}")
                break
    model.load_state_dict(best_state)  # 최적 가중치 복원
    return model, best_val
Output: 조기종료 @ epoch 37, best_val=0.00294

핵심 정리. 금융 딥러닝의 안정화는 화려한 기법이 아니라 기본기다. (1) 입력을 미리 정규화하고, (2) weight decay + dropout으로 규제하고, (3) valid 손실로 조기종료하고, (4) RNN이면 gradient clipping을 켜고, (5) 마지막에 seed 앙상블로 분산을 없앤다. 이 다섯이 없으면 결과가 seed마다 널뛰어 재현이 불가능하다.

4.2 왜 앙상블이 "필수"인가

단일 신경망은 seed(가중치 초기화 + 배치 순서)에 따라 다른 국소최적에 수렴한다. 신호가 강하면 어디로 수렴하든 비슷하지만, 금융처럼 신호 대 잡음비가 낮으면 seed마다 완전히 다른 함수를 학습한다. 개별 예측의 분산이 크다는 뜻이다.

Definition 4.1 — 앙상블의 분산 감소

\[ \hat{y}_{\text{ens}} = \frac{1}{K}\sum_{k=1}^{K}\hat{y}^{(k)}, \qquad \text{Var}(\hat{y}_{\text{ens}}) = \frac{\sigma^2}{K}\big(1+(K-1)\rho\big) \]

↑ K개 모델 예측을 평균하면, 예측 간 상관 \(\rho\)가 낮을수록 분산이 크게 줄어든다. seed만 다른 신경망들은 예측이 완벽히 상관되지 않으므로(\(\rho<1\)) 평균이 개별보다 안정적이고 정확해진다. 이것이 GKX가 10-seed 앙상블을 쓴 이유다.

import numpy as np, torch

def train_seed_ensemble(make_model, train_loader, valid_loader,
                         X_test, seeds=range(10), device="cpu"):
    """서로 다른 seed로 K개 모델을 학습하고 테스트 예측을 평균한다."""
    preds = []
    for s in seeds:
        torch.manual_seed(s); np.random.seed(s)     # seed 고정
        model = make_model()
        model, _ = train_with_recipe(model, train_loader, valid_loader, device=device)
        model.eval()
        with torch.no_grad():
            p = model(torch.tensor(X_test, dtype=torch.float32).to(device)).cpu().numpy()
        preds.append(p)
    preds = np.stack(preds)                          # (K, n_test)
    return preds.mean(0), preds                       # 앙상블 예측, 개별 예측

# 사용 예 (loader들은 §2, §3에서 만든 것)

                                          train_loader, valid_loader, X_test)
# 개별 seed 예측끼리 얼마나 다른지 = 불안정성 진단
print(f"seed 간 예측 표준편차(평균): {all_preds.std(0).mean():.5f}")
print(f"앙상블이 개별 대비 분산 감소를 준다")
Output: 조기종료 @ epoch 33, best_val=0.00291 ... (seed 10개 반복) ... seed 간 예측 표준편차(평균): 0.00612 앙상블이 개별 대비 분산 감소를 준다

단일 seed 결과를 논문에 쓰지 마라. "우리 모델이 벤치마크를 이겼다"가 사실은 운 좋은 seed 하나였던 경우가 학계에서도 흔하다. 최소 다섯, 가급적 열 개의 seed로 학습해 평균 ± 표준편차를 보고해야 한다. 앙상블 예측 하나만 보고하지 말고, seed 간 성능 분포도 함께 제시하는 것이 정직한 연구다.

5. 시계열 모델 — RNN → LSTM → GRU와 현실적 기대

MLP는 각 종목-월을 독립 표본으로 본다. 하지만 수익률에는 시간 구조(모멘텀, 평균회귀)가 있을 수 있다. 순환 신경망(RNN)은 시퀀스를 처리한다. 구조를 수식으로 보되, 기대치를 미리 낮추는 것이 이 절의 진짜 목표다.

5.1 RNN → LSTM → GRU 구조

Definition 5.1 — 바닐라 RNN

\[ h_t = \tanh\!\big(W_{hh}h_{t-1} + W_{xh}x_t + b_h\big) \]

↑ 은닉상태 \(h_t\)는 "지금까지의 요약"이고, 매 시점 이전 요약 \(h_{t-1}\)과 새 입력 \(x_t\)를 섞어 갱신한다. 문제는 시간이 길어지면 \(W_{hh}\)의 반복 곱으로 그래디언트가 소실/폭발한다는 것.

Definition 5.2 — LSTM 게이트

\[ f_t=\sigma(W_f[h_{t-1},x_t]),\quad i_t=\sigma(W_i[\cdot]),\quad o_t=\sigma(W_o[\cdot]) \]
\[ c_t = f_t\odot c_{t-1} + i_t\odot\tanh(W_c[h_{t-1},x_t]),\qquad h_t = o_t\odot\tanh(c_t) \]

↑ LSTM은 셀 상태 \(c_t\)라는 "장기 기억 통로"를 두고, 망각 게이트 \(f_t\)(무엇을 지울까), 입력 게이트 \(i_t\)(무엇을 저장할까), 출력 게이트 \(o_t\)(무엇을 내보낼까)로 정보 흐름을 조절한다. \(\odot\)는 원소별 곱. 게이트 덕분에 그래디언트가 셀 상태를 따라 멀리 흐를 수 있다.

Definition 5.3 — GRU (LSTM의 경량화)

\[ z_t=\sigma(W_z[h_{t-1},x_t]),\quad r_t=\sigma(W_r[h_{t-1},x_t]) \]
\[ h_t = (1-z_t)\odot h_{t-1} + z_t\odot\tanh\!\big(W_h[r_t\odot h_{t-1},x_t]\big) \]

↑ GRU는 게이트를 2개(업데이트 \(z_t\), 리셋 \(r_t\))로 줄이고 셀 상태를 없앤 LSTM의 간소화 버전. 파라미터가 적어 데이터가 짧은 금융에서 오히려 유리한 경우가 많다.

Table 5.1. RNN 계열 비교
모델게이트 수장기 의존성파라미터금융에서
Vanilla RNN0약함 (소실)최소거의 안 씀

import torch, torch.nn as nn

class LSTMForecaster(nn.Module):
    """과거 T개월 시퀀스 → 다음 달 수익률."""
    def __init__(self, n_features, hidden=16, layers=1, p_drop=0.2):
        super().__init__()
        self.lstm = nn.LSTM(n_features, hidden, num_layers=layers,
                            batch_first=True, dropout=0.0 if layers==1 else p_drop)
        self.head = nn.Sequential(nn.LayerNorm(hidden), nn.Dropout(p_drop),
                                  nn.Linear(hidden, 1))
    def forward(self, x):        # x: (batch, T, n_features)
        out, (h_n, c_n) = self.lstm(x)
        last = out[:, -1, :]     # 마지막 시점의 은닉상태만 사용
        return self.head(last).squeeze(-1)

# 입력 예시: 배치 128, 과거 12개월, 특성 20개

model = LSTMForecaster(n_features=20, hidden=16)

6. Attention과 Transformer — self-attention을 코드와 1:1로

Transformer는 순환 없이 어텐션(attention)만으로 시퀀스를 처리한다. 각 시점이 다른 모든 시점을 "얼마나 참고할지" 가중치를 학습한다. 수식과 코드를 한 줄씩 맞춰보자.

6.1 Scaled Dot-Product Attention

Definition 6.1 — Self-Attention

\[ Q=XW_Q,\quad K=XW_K,\quad V=XW_V \]
\[ \text{Attention}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V \]

↑ 입력 \(X\)를 세 번 선형변환해 질의(Query), 열쇠(Key), 값(Value)을 만든다. \(QK^\top\)은 "각 시점이 다른 시점과 얼마나 맞는가"의 유사도 행렬이고, \(\sqrt{d_k}\)로 나눠 스케일을 안정화한 뒤 softmax로 가중치를 만들어 \(V\)를 가중합한다. 즉 내용 기반으로 시점들을 섞는다.

import torch, torch.nn as nn, math

class SelfAttention(nn.Module):
    def __init__(self, d_model, d_k):
        super().__init__()
        self.Wq = nn.Linear(d_model, d_k, bias=False)   # Q = X W_Q
        self.Wk = nn.Linear(d_model, d_k, bias=False)   # K = X W_K
        self.Wv = nn.Linear(d_model, d_k, bias=False)   # V = X W_V
        self.d_k = d_k
    def forward(self, x):                 # x: (batch, T, d_model)
        Q, K, V = self.Wq(x), self.Wk(x), self.Wv(x)
        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)  # QKᵀ/√d_k
        attn = torch.softmax(scores, dim=-1)               # 가중치 행렬
        return attn @ V, attn                                # 가중합, 어텐션 맵

x = torch.randn(2, 12, 16)      # 배치 2, 12개월, d_model=16
sa = SelfAttention(d_model=16, d_k=16)
out, attn = sa(x)
print(f"출력: {out.shape}, 어텐션 맵: {attn.shape}")
print(f"어텐션 각 행의 합(=1 이어야): {attn[0,0].sum().item():.4f}")
Output: 출력: torch.Size([2, 12, 16]), 어텐션 맵: torch.Size([2, 12, 12]) 어텐션 각 행의 합(=1 이어야): 1.0000

6.2 Positional Encoding

어텐션은 순서를 모른다(집합처럼 처리). 그래서 위치 정보를 입력에 더해준다.

Definition 6.2 — Sinusoidal Positional Encoding

\[ PE_{(pos,2i)}=\sin\!\Big(\frac{pos}{10000^{2i/d}}\Big),\qquad PE_{(pos,2i+1)}=\cos\!\Big(\frac{pos}{10000^{2i/d}}\Big) \]

↑ 위치 \(pos\)마다 서로 다른 주파수의 사인·코사인 패턴을 만들어 입력 임베딩에 더한다. 덕분에 모델이 "몇 번째 시점인지"를 구분할 수 있다. 시계열에서는 인과 마스크(causal mask)를 함께 써서 미래를 못 보게 막는다.

6.3 소형 Transformer와 PatchTST 아이디어

import torch, torch.nn as nn, math

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=64):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(max_len).unsqueeze(1).float()
        div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0)/d_model))
        pe[:, 0::2] = torch.sin(pos*div); pe[:, 1::2] = torch.cos(pos*div)
        self.register_buffer("pe", pe)     # 학습 안 되는 버퍼
    def forward(self, x):
        return x + self.pe[:x.size(1)].unsqueeze(0)

class TinyTransformer(nn.Module):
    """소형 Transformer 인코더로 시퀀스 → 다음 달 수익률."""
    def __init__(self, n_features, d_model=16, nhead=2, nlayers=1):
        super().__init__()
        self.embed = nn.Linear(n_features, d_model)
        self.pos = PositionalEncoding(d_model)
        enc = nn.TransformerEncoderLayer(d_model, nhead, dim_feedforward=32,
                                         batch_first=True, dropout=0.2)
        self.encoder = nn.TransformerEncoder(enc, nlayers)
        self.head = nn.Linear(d_model, 1)
    def forward(self, x):            # (batch, T, n_features)
        h = self.pos(self.embed(x))
        h = self.encoder(h)          # (batch, T, d_model)
        return self.head(h[:, -1, :]).squeeze(-1)

model = TinyTransformer(n_features=20)
x = torch.randn(64, 12, 20)
print(f"출력: {model(x).shape}, 파라미터: {sum(p.numel() for p in model.parameters())}")
Output: 출력: torch.Size([64]), 파라미터: 3665

PatchTST 아이디어. 최근 시계열 Transformer의 핵심 트릭은 패칭(patching)이다. 시퀀스를 매 시점 하나씩 토큰으로 만들지 않고, 겹치지 않는 구간(패치)으로 묶어 한 토큰으로 만든다. 이렇게 하면 (1) 어텐션 길이가 짧아져 계산이 줄고, (2) 국소 패턴을 보존하며, (3) 각 채널(특성)을 독립적으로 처리(channel-independence)해 과적합을 줄인다. 금융처럼 데이터가 짧고 잡음이 많은 경우, 이런 파라미터 절약형 설계가 순수 어텐션보다 안전하다.

Transformer를 금융에 그대로 들이밀지 마라. Transformer는 데이터가 많을 때 빛난다. 월별 수익률 패널은 표본이 수만~수십만이라 커 보이지만, 독립적인 시간 관측은 겨우 수백 개월에 불과하다. 큰 Transformer는 이 짧은 시간축에 순식간에 과적합한다. 반드시 작게(층 1~2개, d_model 16~32) 시작하고, §9의 함정 목록을 곱씹으며 valid로 검증하라.

7. Conditional Autoencoder — 딥러닝으로 쓴 비선형 팩터모형

이제 이 라운드의 앵커 논문, GKX(2021)의 Conditional Autoencoder(CA)로 간다. 이 모델의 아름다움은 딥러닝을 자산가격결정 이론의 언어로 다시 썼다는 데 있다.

7.1 선형 팩터모형에서 출발

Definition 7.1 — 정적 팩터모형

\[ r_{i,t} = \beta_i^\top f_t + \epsilon_{i,t} \]

↑ 종목 i의 수익률 = 팩터 로딩(베타) \(\beta_i\)와 공통 팩터 \(f_t\)의 내적 + 고유오차. Fama-French가 이 형태다. 문제: 베타 \(\beta_i\)가 시간에 고정이고, 팩터 \(f_t\)가 관측되어야 한다.

7.2 조건부 오토인코더 — 베타를 특성의 함수로

Definition 7.2 — Conditional Autoencoder (GKX 2021)

\[ r_{i,t} = \underbrace{\beta(z_{i,t-1})}_{\text{베타 네트워크}}^{\top}\ \underbrace{f_t(r_t)}_{\text{팩터 네트워크}} + \epsilon_{i,t} \]

↑ 두 신경망이 함께 작동한다. 베타 네트워크는 종목 특성 \(z_{i,t-1}\)(과거 정보)를 받아 조건부 로딩 \(\beta\)를 비선형으로 만든다. 팩터 네트워크는 그 시점의 수익률(횡단면 포트폴리오)에서 잠재 팩터 \(f_t\)를 뽑는다. 둘의 내적이 수익률을 재구성한다.

왜 "오토인코더"인가? 팩터 네트워크는 그 시점 종목 수익률을 소수의 잠재 팩터로 압축(encode)했다가, 베타와 내적해 다시 모든 종목 수익률로 복원(decode)한다. 입력을 저차원으로 눌렀다 복원하는 오토인코더 구조 그대로다. 다만 인코딩이 종목 특성 \(z\)에 조건부라서 "조건부 오토인코더"다. 결국 이것은 베타가 특성의 비선형 함수인 팩터모형 — 계량경제 모형의 자연스러운 일반화다.

7.3 간소화 구현

import torch, torch.nn as nn

class ConditionalAutoencoder(nn.Module):
    """GKX(2021) 조건부 오토인코더의 간소화 버전.
    베타 네트워크: 종목특성 z -> (N, K) 로딩
    팩터 네트워크: 관리 포트폴리오 수익률 -> (K,) 잠재 팩터
    재구성:        r_hat = beta @ f  (종목별)
    """
    def __init__(self, n_char, n_port, K=4, hidden=16):
        super().__init__()
        # 베타 네트워크: 특성 -> K개 로딩 (종목마다 적용)
        self.beta_net = nn.Sequential(
            nn.Linear(n_char, hidden), nn.ReLU(),
            nn.Linear(hidden, K))
        # 팩터 네트워크: 횡단면 포트폴리오 수익률 -> K개 팩터
        self.factor_net = nn.Sequential(
            nn.Linear(n_port, hidden), nn.ReLU(),
            nn.Linear(hidden, K))
    def forward(self, z, port_ret):     # z: (N, n_char), port_ret: (n_port,)
        beta = self.beta_net(z)          # (N, K)  조건부 로딩
        f = self.factor_net(port_ret)    # (K,)    잠재 팩터
        r_hat = beta @ f                 # (N,)    재구성 수익률
        return r_hat, beta, f

# 한 시점: 종목 500개, 특성 20개, 관리 포트폴리오 20개, 잠재 팩터 4개
N, n_char, n_port, K = 500, 20, 20, 4
model = ConditionalAutoencoder(n_char, n_port, K)
z = torch.randn(N, n_char)
port_ret = torch.randn(n_port)         # 특성-정렬 포트폴리오 수익률
r_hat, beta, f = model(z, port_ret)
print(f"재구성 수익률 r_hat: {r_hat.shape}")
print(f"조건부 로딩 beta: {beta.shape}, 잠재 팩터 f: {f.shape}")
Output: 재구성 수익률 r_hat: torch.Size([500]) 조건부 로딩 beta: torch.Size([500, 4]), 잠재 팩터 f: torch.Size([4])

Definition 7.3 — CA의 학습 손실

\[ \min_{\theta}\ \frac{1}{T}\sum_{t}\ \big\lVert r_t - \beta(z_{t-1})\,f_t \big\rVert_2^2 \]

↑ 매 시점, 실제 수익률 벡터 \(r_t\)와 재구성 \(\beta f_t\)의 오차를 최소화한다. 베타는 과거 특성 \(z_{t-1}\)만 쓰므로 예측에 쓸 수 있다(누수 없음). 잠재 팩터 개수 K는 하이퍼파라미터로, GKX는 K를 늘려가며 out-of-sample 설명력을 비교했다.

핵심 정리. CA는 "딥러닝 vs 계량경제"라는 이분법을 무너뜨린다. 베타를 특성의 신경망으로 만들면, 팩터모형이 곧 딥러닝이 된다. GKX(2021)는 이 CA가 선형 팩터모형(IPCA 포함)보다 out-of-sample \(R^2\)와 포트폴리오 샤프비율에서 우수함을 보였다. R10의 재현 프로젝트에서 이 모델을 직접 학습하게 될 것이다.

9. 과적합과의 전쟁 — 금융 DL이 실패하는 전형

금융 딥러닝은 실패가 기본값이다. 성공 사례보다 실패 패턴을 아는 것이 훨씬 유용하다. 아래는 반복적으로 관찰되는 실패의 전형이다.

Definition 9.1 — 금융 DL 실패 패턴 목록

  1. 과도한 깊이/폭. 층을 쌓을수록 좋아진다는 이미지 도메인의 직관을 그대로 적용 → 짧은 시간축에 즉시 과적합. GKX는 NN3 > NN5.
  2. 튜닝 과적합(선택 편향). 하이퍼파라미터를 테스트셋 성능을 보며 고르면, 테스트셋이 사실상 학습에 쓰인다. valid로만 고르고 test는 마지막에 한 번만 본다.
  3. 짧은 데이터. 독립적 시간 관측이 수백 개월뿐. "표본 수만 개"에 속아 큰 모델을 쓴다.
  4. 미세한 누수. 정규화 통계 누수(§2), 미래를 포함한 윈도우(§5), 상장폐지 생존편향(R2) 등.
  5. 불안정성 은폐. 운 좋은 단일 seed만 보고(§4).
  6. 비정상성 무시. 시장 레짐이 바뀌면 과거 패턴이 사라진다. 워크포워드 재학습으로만 방어 가능.

Definition 9.2 — 편향-분산 관점의 과적합

\[ \mathbb{E}\big[(y-\hat{f})^2\big] = \underbrace{\text{Bias}^2}_{\text{모델이 단순}} + \underbrace{\text{Var}}_{\text{데이터에 민감}} + \underbrace{\sigma^2}_{\text{줄일 수 없는 잡음}} \]

↑ 금융은 \(\sigma^2\)(줄일 수 없는 잡음)이 지배적이다. 신호가 약하므로, 복잡한 모델로 편향을 줄이려 해봐야 분산만 폭증한다. 그래서 얕은 모델 + 강한 규제 + 앙상블(분산 감소)이 이긴다. "얕은 네트워크가 이긴다"는 GKX의 발견은 이 분해로 정확히 설명된다.

10.1 평가 지표 재사용 (R8)

Definition 10.1 — Out-of-sample R²와 랭크 IC

\[ R^2_{oos} = 1 - \frac{\sum_{(i,t)\in\text{test}}(r_{i,t}-\hat{r}_{i,t})^2}{\sum_{(i,t)\in\text{test}} r_{i,t}^2},\qquad \text{IC}_t = \text{corr}\big(\text{rank}(\hat{r}_{\cdot,t}),\ \text{rank}(r_{\cdot,t})\big) \]

↑ GKX 스타일 \(R^2_{oos}\)는 분모에 평균을 빼지 않는다(무조건부 예측이 0이라는 귀무가설 대비). 랭크 IC는 각 시점 예측 순위와 실제 순위의 상관 — 롱숏 포트폴리오 수익성과 직결된다. 두 지표 모두 R8에서 정의한 그대로다.

10.2 통일된 평가 루프

import numpy as np, pandas as pd
from scipy.stats import spearmanr

def oos_r2(y_true, y_pred):
    """GKX 스타일 OOS R² (평균 차감 없음)."""
    return 1.0 - np.sum((y_true - y_pred)**2) / np.sum(y_true**2)

def mean_rank_ic(df):
    """시점별 랭크 IC의 시계열 평균 (df: date, y_true, y_pred)."""
    ics = df.groupby("date").apply(
        lambda g: spearmanr(g["y_pred"], g["y_true"]).correlation)
    return ics.mean(), ics.std()

def evaluate(name, y_true, y_pred, dates):
    df = pd.DataFrame({"date": dates, "y_true": y_true, "y_pred": y_pred})
    r2 = oos_r2(y_true, y_pred)
    ic_mean, ic_std = mean_rank_ic(df)
    icir = ic_mean / ic_std * np.sqrt(12)   # 연율화 IC 정보비율
    return {"model": name, "oos_r2(%)": round(r2*100, 3),
            "ic": round(ic_mean, 4), "icir": round(icir, 2)}

Quiz

Q1. 학습 루프에서 optimizer.zero_grad()를 빼먹으면 어떤 일이 벌어지는가?
PyTorch의 .grad는 .backward()마다 덮어쓰지 않고 누적(accumulate)된다. 따라서 zero_grad를 빼먹으면 매 스텝의 그래디언트가 계속 더해져, 실질 학습률이 폭증하고 파라미터가 발산한다. 5단계(zero_grad→forward→loss→backward→step) 중 첫 단계를 지키는 것이 필수다.
Q2. 금융 횡단면 신경망에서 BatchNorm보다 LayerNorm이 선호되는 이유는?
BatchNorm은 배치 통계(mean/std)에 의존하는데, 금융 배치는 종목 구성과 시점이 섞여 통계가 불안정하고, 여러 시점을 섞으면 미묘한 정보 혼합이 생길 수 있다. 반면 LayerNorm은 각 샘플 내부(특성 방향)에서만 정규화하므로 배치 구성·시점에 무관해 재현성이 좋다. 시계열/Transformer 계열에서 특히 중요하다.
Q3. GKX가 단일 신경망이 아니라 10-seed 앙상블을 보고한 이유를 분산 감소 공식으로 설명하라.
신호 대 잡음비가 낮으면 개별 신경망 예측의 분산 \(\sigma^2\)이 크고 seed마다 다른 함수를 학습한다. K개 예측을 평균하면 분산이 \(\frac{\sigma^2}{K}(1+(K-1)\rho)\)로 줄어든다(\(\rho\)=예측 간 상관). seed만 다른 모델들은 \(\rho<1\)이라 평균이 개별보다 안정적이고 정확하다. 따라서 앙상블은 선택이 아니라 필수다.
Q4. 아래 코드의 누수 버그를 찾아라.
scaler = StandardScaler().fit(X_all); Xtr = scaler.transform(X_train); Xte = scaler.transform(X_test)
정규화 통계(mean/std)를 전체 데이터 X_all(테스트 포함)에서 계산했다. 이러면 테스트 기간의 분포 정보가 학습에 새어든다(look-ahead leakage). 올바른 코드는 scaler.fit(X_train)으로 학습셋에서만 fit하고, test에는 transform만 적용하는 것이다. 딥러닝 파이프라인에서 가장 흔하고 은밀한 누수다.
Q5. self-attention에서 \(QK^\top\)을 \(\sqrt{d_k}\)로 나누는 이유는?
\(Q\)와 \(K\)의 차원 \(d_k\)가 커지면 내적 \(QK^\top\)의 분산이 \(d_k\)에 비례해 커진다. 그대로 softmax에 넣으면 값이 극단으로 몰려 그래디언트가 소실된다(포화). \(\sqrt{d_k}\)로 나눠 스케일을 안정화하면 softmax가 부드러운 분포를 유지해 학습이 안정된다. 그래서 "scaled" dot-product attention이라 부른다.
Q6. Conditional Autoencoder(GKX 2021)에서 베타 네트워크의 입력이 \(z_{i,t-1}\)(과거 특성)인 것이 왜 중요한가?
베타 \(\beta(z_{i,t-1})\)가 시점 t 이전 정보만 쓰므로, 시점 t의 수익률을 예측하는 데 써도 미래 정보 누수가 없다. 만약 동시점 특성 \(z_{i,t}\)를 쓰면 예측 시점에 알 수 없는 정보를 쓰게 되어 실전 배포가 불가능하다. 이 시차 구조가 "예측 가능한 팩터모형"을 만드는 핵심이다.
Q7. "얕은 네트워크가 이긴다"(NN3 > NN5)를 편향-분산 분해로 설명하라.
기대 오차 = Bias² + Var + 줄일 수 없는 잡음 \(\sigma^2\). 금융은 \(\sigma^2\)이 지배적(낮은 SNR)이다. 층을 늘려 편향을 조금 줄여도, 짧은 데이터에서 분산이 훨씬 크게 증가한다. 결국 총 오차의 최적점이 낮은 복잡도 쪽에 있어 NN3가 NN5를 이긴다. 데이터가 지원하는 만큼만 복잡하게 만드는 것이 정답이다.
Q8. "테스트셋 성능을 보며 하이퍼파라미터를 골랐다"가 왜 문제인가?
테스트셋이 사실상 학습(모델 선택)에 쓰여, 보고된 성능이 낙관적으로 부풀려진다(튜닝 과적합/선택 편향). 수백 번의 실험 중 최고를 고르면 그것이 우연히 좋았을 가능성이 크다(다중비교). 올바른 절차: 하이퍼파라미터는 validation으로만 고르고, 테스트셋은 모든 개발이 끝난 뒤 딱 한 번 연다.
Q9. RNN 계열에 gradient clipping이 사실상 필수인 이유는?
RNN은 시간 전개에서 같은 가중치 \(W_{hh}\)를 반복 곱하므로, 시퀀스가 길면 그래디언트가 지수적으로 폭발(또는 소실)한다. 폭발하면 파라미터가 한 스텝에 발산한다. clipping은 그래디언트 노름이 임계값 c를 넘으면 방향은 유지한 채 크기만 c로 잘라 폭주를 막는다(clip_grad_norm_). LSTM/GRU도 완전히 자유롭지 않아 켜두는 것이 안전하다.
Q10. 아래 LSTM 데이터 준비 코드의 위험을 지적하라.
seq = returns[t-11 : t+1] # 과거 12개월; y = returns[t]
입력 시퀀스 returns[t-11:t+1]는 인덱스 t까지 포함하는데, 타깃이 returns[t]다. 즉 맞춰야 할 값이 입력에 들어가 있다(look-ahead 누수). 올바른 설계는 입력을 returns[t-12:t](과거 12개월, t 미포함)로 하고 타깃을 returns[t]로 두는 것. 시퀀스 윈도우가 미래(또는 타깃 시점)를 포함하지 않도록 항상 확인해야 한다.
